## 문제. 음악 재생 목록 관리 웹 앱

서로 다른 정렬 알고리즘으로 노래를 여러 기준에 따라 정렬하는 **음악 재생 목록 관리** 웹 앱을 만든다. 재생 목록이 커질 때 정렬 성능이 어떻게 달라지는지 비교한다.

- **백엔드:** Python (FastAPI 또는 Flask)
- **프런트엔드:** HTML, CSS, JavaScript

### 1. 정렬 알고리즘

최소한 다음 **세 가지 정렬 알고리즘**을 구현한다.

| 알고리즘 | 최악의 경우 |
|:-----|:-----|
| 선택 정렬 (Selection Sort) | O(n²) |
| 삽입 정렬 (Insertion Sort) | O(n²) |
| 병합 정렬 (Merge Sort) | O(n log n) |

*표 1. 최소한 구현할 세 가지 정렬 알고리즘*

각 알고리즘은 사용자가 고른 기준인 **제목**(title), **아티스트**(artist), **재생 시간**(duration), **재생 횟수**(play count) 중 하나로 재생 목록을 정렬해야 한다.

### 2. 웹 인터페이스

- 제목, 아티스트, 재생 시간, 재생 횟수를 보여 주는 **재생 목록 표**를 둔다.
- 노래 N곡의 재생 목록을 만드는 **"Generate Random"** 버튼을 둔다.
- 정렬 기준과 정렬 알고리즘을 고르는 **드롭다운**을 둔다.
- **"Sort"** 버튼은 정렬된 결과, 비교 횟수, 교환 횟수, 실행 시간을 보여 준다.
- **"Compare All"** 버튼은 모든 알고리즘을 실행하고 비교 표를 보여 준다.

### 3. API 엔드포인트

| 메서드 | 엔드포인트 | 설명 |
|:-----|:-----|:-----|
| `POST` | `/sort` | 고른 알고리즘과 기준으로 재생 목록을 정렬 |
| `POST` | `/compare` | 모든 알고리즘을 실행하고 비교 데이터를 반환 |
| `POST` | `/generate` | 노래 N곡의 무작위 재생 목록을 생성 |
| `GET` | `/` | 프런트엔드 페이지 제공 |

*표 2. 구현할 API 엔드포인트*
