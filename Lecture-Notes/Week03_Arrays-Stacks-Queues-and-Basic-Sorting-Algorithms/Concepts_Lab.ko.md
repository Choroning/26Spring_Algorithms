## 2. Type A: 알고리즘 구현

### 2.1 A-1: 기초 정렬 알고리즘

#### 2.1.1 선택 정렬

**아이디어**: 최솟값을 찾아 앞으로 교환하는 과정을 반복한다.

```text
[64, 34, 25, 12, 22, 11, 90]

Pass 1: 최소=11 찾기    -> [11, 34, 25, 12, 22, 64, 90]
                            ^^
Pass 2: 최소=12 찾기    -> [11, 12, 25, 34, 22, 64, 90]
                                ^^
Pass 3: 최소=22 찾기    -> [11, 12, 22, 34, 25, 64, 90]
                                    ^^
Pass 4: 최소=25 찾기    -> [11, 12, 22, 25, 34, 64, 90]
                                        ^^
완료!                     [11, 12, 22, 25, 34, 64, 90]
```

*그림 1. 선택 정렬의 패스별 배열 상태*

**복잡도**: O(n²)이다. 항상 나머지 원소를 모두 스캔한다.

> **참고:** 3주차 이론에서는 최댓값을 찾아 뒤로 보내는 방식으로 설명했지만, 이 실습에서는 최솟값을 찾아 앞으로 보내는 방식을 사용한다. 두 방식 모두 선택 정렬이며, 복잡도는 동일하다. 방향만 다를 뿐 핵심 원리(매 라운드마다 하나의 원소를 확정)는 같다.

**풀이:**

```python
def selection_sort(arr):
    """Selection Sort: 최솟값을 찾아 앞으로 교환. O(n²)"""
    a = arr[:]
    n = len(a)
    for i in range(n):
        min_idx = i
        for j in range(i + 1, n):
            if a[j] < a[min_idx]:
                min_idx = j
        a[i], a[min_idx] = a[min_idx], a[i]
    return a

# 사용 예시:
print(selection_sort([64, 34, 25, 12, 22, 11, 90]))
# 출력: [11, 12, 22, 25, 34, 64, 90]
```

> **참고:** `arr[:]`는 배열의 **얕은 복사(shallow copy)** 이다. 원본 배열을 수정하지 않고 복사본에서 정렬하기 위한 것이다. `a[i], a[min_idx] = a[min_idx], a[i]`는 Python의 동시 할당(simultaneous assignment)으로, 별도의 임시 변수 없이 두 값을 교환한다.

#### 2.1.2 버블 정렬

**아이디어**: 인접한 원소를 반복적으로 비교하고 순서가 잘못되면 교환한다. 가장 큰 원소가 끝으로 올라간다(bubble up).

```text
[64, 34, 25, 12]

Pass 1: [34, 64, 25, 12]  swap(64,34)
        [34, 25, 64, 12]  swap(64,25)
        [34, 25, 12, 64]  swap(64,12)  <- 64 확정
                     ^^
Pass 2: [25, 34, 12, 64]  swap(34,25)
        [25, 12, 34, 64]  swap(34,12)  <- 34 확정
                 ^^
Pass 3: [12, 25, 34, 64]  swap(25,12)  <- 25 확정
             ^^
완료!   [12, 25, 34, 64]
```

*그림 2. 버블 정렬의 패스별 교환 과정*

**최적화**: 한 패스에서 교환이 없으면 이미 정렬된 것이므로 조기 종료할 수 있다.

**풀이:**

```python
def bubble_sort(arr):
    """Bubble Sort: 인접 원소를 반복 교환. O(n²)"""
    a = arr[:]
    n = len(a)
    for i in range(n):
        swapped = False
        for j in range(0, n - i - 1):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                swapped = True
        if not swapped:
            break
    return a
```

`swapped` 플래그로 조기 종료가 가능하며, 이미 정렬된 입력에서는 최선의 경우 O(n)이다.

여기서 `i`는 패스 번호(0, 1, 2, ...)이다. 패스 `i`가 끝나면 마지막 `i`개 원소가 이미 최종 위치에 있으므로, 안쪽 루프는 인덱스 `n-i-2`까지만 순회하면 된다(즉, `range(0, n-i-1)`).

> **참고:** `n - i - 1`인 이유: 매 패스가 끝날 때마다 오른쪽 끝에 하나씩 원소가 확정되므로, i번째 패스에서는 마지막 i개 원소를 비교할 필요가 없다. 이 최적화가 없어도 정확성은 같지만, 불필요한 비교를 줄여 준다.

#### 2.1.3 삽입 정렬

**아이디어**: 각 원소를 이미 정렬된 접두사의 올바른 위치에 삽입한다.

```text
[64, 34, 25, 12, 22]

Step 1: [64 | 34, 25, 12, 22]  34 삽입 -> [34, 64 | 25, 12, 22]
Step 2: [34, 64 | 25, 12, 22]  25 삽입 -> [25, 34, 64 | 12, 22]
Step 3: [25, 34, 64 | 12, 22]  12 삽입 -> [12, 25, 34, 64 | 22]
Step 4: [12, 25, 34, 64 | 22]  22 삽입 -> [12, 22, 25, 34, 64]

        정렬된 부분 | 미정렬된 부분
```

*그림 3. 삽입 정렬의 단계별 삽입 과정*

**최선의 경우**: 이미 정렬된 데이터에서 O(n)이고, 거의 정렬된 데이터에서도 O(n)에 가깝게 동작하므로 소규모 데이터나 거의 정렬된 데이터에 유리하다.

**풀이:**

```python
def insertion_sort(arr):
    """Insertion Sort: 각 원소를 정렬된 접두사에 삽입. O(n²)"""
    a = arr[:]
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key
    return a
```

> **참고:** 코드를 한 줄씩 분석하면 다음과 같다.
> - `key = a[i]`: 삽입할 원소를 저장한다.
> - `while j >= 0 and a[j] > key`: key보다 큰 원소를 만나는 동안 반복한다.
> - `a[j + 1] = a[j]`: 큰 원소를 오른쪽으로 한 칸 밀어낸다.
> - `a[j + 1] = key`: 빈자리에 key를 삽입한다.
>
> 이미 정렬된 배열에서는 `a[j] > key` 조건이 바로 거짓이므로 while문이 실행되지 않아 O(n)이다.

### 2.2 A-2: 고급 정렬 알고리즘

> **[자료구조]** 자료구조에서 다루는 **재귀(recursion)** 는 함수가 기저 사례에 도달할 때까지 더 작은 입력으로 자기 자신을 호출하는 기법이다. 아래의 병합 정렬과 퀵 정렬은 배열을 나눈 뒤 각 부분에 같은 함수를 재귀 호출하므로 재귀의 동작을 알아야 이해할 수 있으며, 재귀의 기본은 2주차 이론의 재귀 절에서 다룬다.

#### 2.2.1 병합 정렬

**아이디어**: 배열을 반으로 나누고, 각 반을 재귀적으로 정렬한 후 병합한다.

```text
         [38, 27, 43, 3, 9, 82, 10]
                    /     \
         [38, 27, 43, 3]   [9, 82, 10]
            /     \           /     \
       [38, 27]  [43, 3]  [9, 82]  [10]
        /   \     /   \    /   \      |
      [38] [27] [43]  [3] [9] [82]  [10]
        \   /     \   /    \   /      |
       [27, 38]  [3, 43]  [9, 82]  [10]
            \     /           \     /
        [3, 27, 38, 43]   [9, 10, 82]
                    \     /
         [3, 9, 10, 27, 38, 43, 82]
```

*그림 4. 병합 정렬의 분할과 병합 트리*

**복잡도**: O(n log n)이며, 입력과 관계없이 항상 보장된다.

> **핵심:** 위 트리를 보면 분할 정복의 3단계가 명확하다.
> - 위→아래(분할): 배열을 반씩 나눈다(총 log n 레벨).
> - 맨 아래(기저): 원소 1개는 자명하게 정렬되어 있다.
> - 아래→위(결합): 정렬된 부분 배열을 병합한다.

**풀이:**

```python
def merge_sort(arr):
    """Merge Sort: 분할, 반쪽 정렬, 병합. O(n log n)"""
    if len(arr) <= 1:
        return arr[:]
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    return _merge(left, right)

def _merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result
```

> **참고:** `_merge` 함수에서 `left[i] <= right[j]`의 `<=`(등호 포함)가 중요하다. `<`로 바꾸면 값이 같은 원소의 상대적 순서가 바뀔 수 있어 **안정성(stability)** 이 깨진다. 안정 정렬이 필요할 때 반드시 `<=`를 사용해야 한다.

> **참고:** 그림 4는 7개 원소를 왼쪽 4개, 오른쪽 3개로 나누었다. 위 코드는 `mid = len(arr) // 2 = 3`이므로 왼쪽이 [38, 27, 43], 오른쪽이 [3, 9, 82, 10]이 되어 중간 단계의 부분 배열은 그림과 다르지만, 최종 결과는 같다.

**병합 추적([27, 38]과 [3, 43]의 병합):** i=0, j=0: 27 vs 3 비교 -> 3 선택. i=0, j=1: 27 vs 43 비교 -> 27 선택. i=1, j=1: 38 vs 43 비교 -> 38 선택. 나머지 43 추가. 결과: [3, 27, 38, 43].

#### 2.2.2 퀵 정렬

**아이디어**: 피벗을 선택하고, 피벗보다 작은 원소, 같은 원소, 큰 원소로 분할한 후 재귀한다.

```text
피벗 = 43
[38, 27, 43, 3, 9, 82, 10]

       < 43          == 43    > 43
[38, 27, 3, 9, 10]   [43]     [82]
       |                        |
  quicksort(...)          quicksort(...)
       |                        |
[3, 9, 10, 27, 38]             [82]

결과: [3, 9, 10, 27, 38] + [43] + [82]
     = [3, 9, 10, 27, 38, 43, 82]
```

*그림 5. 피벗 43을 기준으로 한 3-way 분할*

**복잡도**: 평균 O(n log n), 최악 O(n²)

최악의 경우 O(n²)은 피벗이 항상 가장 작거나 가장 큰 원소일 때 발생하며, 최대한 불균형한 분할이 만들어진다(예: 이미 정렬된 입력에서 첫 번째 또는 마지막 원소를 피벗으로 사용). 이 경우 재귀가 log n이 아닌 n 레벨로 깊어진다.

**풀이:**

```python
def quick_sort(arr):
    """Quick Sort: 피벗 기준 분할 후 부분 배열 정렬. 평균 O(n log n)."""
    if len(arr) <= 1:
        return arr[:]
    pivot = arr[len(arr) // 2]
    left = [x for x in arr if x < pivot]
    middle = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quick_sort(left) + middle + quick_sort(right)
```

> **참고:** 이 구현은 3주차 이론의 제자리(in-place) 분할과 다르다. 리스트 컴프리헨션(list comprehension)을 사용한 **간결하지만 추가 공간을 사용하는** 버전이다. 장단점은 다음과 같다.
> - **장점**: 코드가 매우 짧고 이해하기 쉬우며, 피벗과 같은 원소를 별도로 처리한다.
> - **단점**: 매 호출마다 새 리스트를 생성하므로 O(n) 추가 공간을 사용한다.
>
> 실무에서는 3주차 이론의 제자리 방식이 메모리 면에서 효율적이지만, 코딩 테스트에서는 이 간결한 방식이 빠르게 구현하기 좋다.

> **참고:** 피벗 선택의 차이는 다음과 같다.
> - **3주차 이론(CLRS)**: 마지막 원소를 피벗으로 사용하는 제자리 Lomuto 분할이다.
> - **이 코드**: 중간 원소를 피벗으로 사용하는 3-way 분할(< / == / >)이다.
>
> 중간 원소를 피벗으로 선택하면 이미 정렬된 입력에서도 균형 잡힌 분할이 되므로 정렬된 입력에서 생기는 최악의 경우를 피할 수 있다(다른 입력에서는 여전히 최악의 경우가 생길 수 있다). CLRS 방식은 3주차와 4주차 이론의 퀵 정렬 분석이 전제하는 표준 분할이므로, 두 방식을 구별해 이해할 필요가 있다. 그림 5는 3-way 분할을 보이기 위해 피벗을 43으로 잡았지만, 이 코드는 인덱스 `len(arr) // 2`의 원소를 피벗으로 쓰므로 같은 배열에서 실제 첫 피벗은 3이다.

> **참고:** **안정성.** 위에서 보인 리스트 컴프리헨션 버전은 실제로 안정적이지만, 퀵 정렬은 일반적으로 불안정(unstable) 정렬로 분류된다. 표준 제자리 분할(CLRS 버전)이 같은 값을 가진 원소들의 상대적 순서를 보존하지 않기 때문이다.

```

#### 2.2.3 정렬 알고리즘 비교

**안정 정렬(stable sort)** 은 키가 같은 원소들의 상대적 순서를 보존하는 정렬이다. **제자리 정렬(in-place sort)** 은 입력 배열을 제외하고 O(1)의 추가 메모리만 사용하는 정렬이다. 재귀 호출 스택이 차지하는 O(log n)은 보통 허용하므로 퀵 정렬도 제자리 정렬로 분류한다.

| 알고리즘 | 최선 | 평균 | 최악 | 안정? | 제자리? |
|:---------|:-----|:-----|:-----|:------|:--------|
| 선택 | O(n²) | O(n²) | O(n²) | 아니오 | 예 |
| 버블 | O(n) | O(n²) | O(n²) | 예 | 예 |
| 삽입 | O(n) | O(n²) | O(n²) | 예 | 예 |
| 병합 | O(n log n) | O(n log n) | O(n log n) | 예 | 아니오 |
| 퀵 | O(n log n) | O(n log n) | O(n²) | 아니오 | 예* |

*표 2. 정렬 알고리즘의 복잡도, 안정성, 제자리 여부 비교*

*\* 위의 리스트 컴프리헨션 버전은 추가 공간을 사용한다.*

> **핵심:** 이 표에서 기억할 점은 다음과 같다.
> - 기초 정렬 중 최선 O(n)인 것은 삽입 정렬과 조기 종료를 적용한 버블 정렬이며, 거의 정렬된 데이터에는 **삽입 정렬**이 특히 유리하다.
> - 이 표에서 **병합 정렬**만 최악에서도 O(n log n)을 보장하므로 성능을 가장 확실하게 예측할 수 있다.
> - **퀵 정렬**은 평균이 가장 빠르지만 최악 O(n²) 위험이 있다.

### 2.3 A-3: 벤치마크

**질문**: N이 몇일 때부터 O(n²)과 O(n log n)의 차이가 눈에 띄는가?

> **핵심:** N=100에서는 모든 알고리즘이 0.001초로 차이가 없지만, N=10,000만 되어도 O(n²)은 수 초, O(n log n)은 수십 밀리초로 **100배 이상** 차이가 난다. N=100,000이면 O(n²)은 수 분~수십 분, O(n log n)은 1초 미만이다. 이 차이에서 알고리즘 선택이 중요하다는 것을 체감할 수 있다.

> **참고:** N=100,000에서 O(n²) 알고리즘은 수 분에서 10분 이상 소요될 수 있다. 프로그램이 멈춘 것이 아니라 실제로 그만큼 오래 걸리는 것이다. 시간이 부족하면 O(n²) 알고리즘은 N=10,000까지만 테스트하고, N=100,000은 O(n log n) 알고리즘만 실행해도 된다.

2 |
  |

```

O(n²) 알고리즘은 극적으로 치솟는 반면, O(n log n) 알고리즘은 이 스케일에서 거의 평평하게 유지된다.

## 점검 문제

1. 벤치마크에서 거의 정렬된 입력에 대해 가장 빠른 기초 정렬은 무엇이었는가? 그 이유는?

   <details>
   <summary>정답</summary>

   **삽입 정렬**이 압도적으로 빠르다. 접두사가 이미 정렬되어 있으면 각 원소의 `while j >= 0 and a[j] > key` 루프가 **거의 즉시 종료** 된다. key는 바로 앞 이웃과 한 번만 비교하여 제자리임을 확인한 뒤 넘어간다. 총 작업량은 최선의 경우인 $\Theta(n)$에 가깝게 줄어든다. **선택 정렬**은 입력 상태와 무관하게 항상 $n(n-1)/2$번의 비교를 수행한다. **버블 정렬**도 `swapped` 플래그가 있으면 완전히 정렬된 입력에서는 $\Theta(n)$이 가능하지만, 거의 정렬된 데이터에서는 제자리보다 오른쪽에 있는 작은 원소가 한 패스에 한 칸씩만 왼쪽으로 이동하므로 그 거리만큼 패스를 더 돌아야 하여 삽입 정렬보다 느리다.

   </details>

2. 리스트 컴프리헨션 버전의 퀵 정렬은 추가 메모리를 사용한다. 얼마나 사용하는가? 대규모 입력에서 CLRS의 제자리(in-place) 버전이 선호되는 이유는?

   <details>
   <summary>정답</summary>

   매 `quick_sort` 호출이 `left`, `middle`, `right` **새 리스트 3개**를 만들고 그 합계는 매 재귀 레벨마다 $O(n)$이다. 평균 깊이 $O(\log n)$에 걸쳐 누적 할당은 $O(n \log n)$이고, 동시 상주 메모리는 평균적으로 최대 $O(n)$이다. **CLRS in-place** 버전은 원본 배열 안에서만 교환하므로 평균 $O(\log n)$의 스택 프레임과 $O(1)$의 보조 데이터만 사용한다. 대규모 입력에서는 잦은 할당이 **가비지 컬렉터**에 부담을 주고 CPU 캐시를 오염시키며, 메모리가 부족한 환경에서는 RAM이 고갈될 수도 있다. 제자리 버전은 연속된 메모리를 접근하므로 캐시 지역성 또한 훨씬 우수하다.

   </details>

3. O(n²)과 O(n log n) 알고리즘 사이의 명확한 성능 차이를 처음 느낀 입력 크기는 얼마인가?

   <details>
   <summary>정답</summary>

   **N = 10,000** 부근에서 격차가 극적으로 드러난다. N=100에서는 모든 알고리즘이 1ms 안에 끝나서 점근적 차이가 상수 인자와 타이머 잡음에 묻혀 버린다. N=1,000에서는 수십 ms 대 수 ms로 차이가 보이지만 아직 사용자가 불편을 느낄 정도는 아니다. **N = 10,000**에서는 차이가 **약 100배**로 커진다. 수 초 대 수십 ms의 차이는 실제 사용자가 지연을 느낄 만한 임계점이다. N=100,000에서는 $O(n^2)$ 알고리즘이 수 분 걸리는 동안 $O(n \log n)$은 1초 안에 끝난다.

   </details>

4. 삽입 정렬의 최악 시간 복잡도가 O(n²)임에도, Timsort와 같은 실용적 구현에서 기저 사례로 사용되는 이유는?

   <details>
   <summary>정답</summary>

   **작은 부분 배열**(보통 크기 32나 64 이하)에 대해서는 점근적 $O(n^2)$이 별 의미가 없다. 그 크기에서는 삽입 정렬의 작은 **상수 인자**, 재귀 오버헤드가 없다는 점, 우수한 **캐시 동작**이 병합 정렬이나 퀵 정렬을 압도한다. 실제 데이터는 **국소적으로 정렬된 구간(run)** 이 많은데, 그런 구간에서 삽입 정렬은 거의 $\Theta(n)$으로 동작한다. Timsort는 이 두 효과를 모두 활용한다. 자연 발생한 run을 식별하고 짧은 run은 삽입 정렬로 확장한 뒤, 큰 run끼리만 병합 정렬로 합친다. 결국 $n$이 작은 상수로 제한된 경우에만 삽입 정렬을 쓰므로 최악 $O(n^2)$이 실제로 나타나지 않는다.

   </details>
