## 1. 해싱의 기초

### 1.1 해싱이란?

**해싱(hashing)** 은 **임의 크기** 의 데이터를 **고정 크기** 데이터로 변환하는 기법이다.

- **키(key)** 를 이용해 **값(value)** 을 빠르게 조회한다.
- 키-값 쌍을 **해시 테이블(hash table)** 에 저장한다.
- **해시 함수(hash function)** 는 키를 데이터가 저장될 **인덱스(index)** 로 변환한다.

```
   Key  ──►  Hash Function  ──►  Hash Value (Index)  ──►  Hash Table
```

**목표:** 탐색, 삽입, 삭제에 대해 **평균 $O(1)$** 시간을 달성한다.

> **이전 주차와의 연결:** 3주차에서 배운 배열은 인덱스만 알면 $O(1)$ 임의 접근을 제공한다. 해싱은 그 빠진 조각 — 키로부터 인덱스를 *직접 계산* 하는 방법 — 을 채워준다.

### 1.2 해시 테이블 구조

해시 테이블은 세 가지 구성 요소로 이루어진다:

| 구성 요소 | 역할 |
|----------|------|
| **Key** | 각 데이터를 식별하는 고유 식별자 |
| **Hash Function** | 키를 해시 값(인덱스)으로 변환 |
| **Hash Table** | 계산된 인덱스 위치에 데이터를 저장하는 배열 |

```
   Key: "Alice"                    Hash Table
        │                    ┌───┬───────────┐
        ▼                    │ 0 │           │
   h("Alice") = 3            │ 1 │           │
        │                    │ 2 │           │
        ▼                    │ 3 │  "Alice"  │ ◄── 여기에 저장
   Index = 3                 │ 4 │           │
                             │ 5 │           │
                             └───┴───────────┘
```

### 1.3 해시 함수

해시 함수 $h(k)$는 키 $k$를 크기 $m$인 테이블의 인덱스로 매핑한다.

**나눗셈법(Division method)** — 가장 흔히 쓰이는 방식:

$$h(k) = k \bmod m$$

**예시** — 테이블 크기 $m = 10$:

| 키 $k$ | $h(k) = k \bmod 10$ | 인덱스 |
|--------|---------------------|--------|
| 25 | 25 mod 10 | 5 |
| 37 | 37 mod 10 | 7 |
| 42 | 42 mod 10 | 2 |
| 55 | 55 mod 10 | 5 |

키 25와 55가 모두 인덱스 5로 매핑된다 — 이것이 **충돌(collision)** 이다.

**곱셈법(Multiplication method)** — 대안:

$$h(k) = \lfloor m \cdot (k \cdot A \bmod 1) \rfloor, \quad 0 < A < 1$$

- $m$의 값이 결정적으로 중요하지 않다 (소수 대 2의 거듭제곱 함정이 없다).
- Knuth는 $A \approx (\sqrt{5} - 1)/2 \approx 0.618$ (황금비의 켤레) 를 제안한다.

### 1.4 좋은 해시 함수의 성질

잘 설계된 해시 함수는 다음을 만족해야 한다:

1. **결정적(Deterministic)** — 같은 키는 항상 같은 해시 값을 만든다.
2. **균등 분포(Uniform distribution)** — 키들이 테이블에 고르게 퍼진다.
3. **효율적(Efficient)** — $O(1)$ 시간에 계산된다.

**$m$ (테이블 크기) 선택:**

- 2의 거듭제곱은 피한다 — $h(k) = k \bmod 2^p$는 $k$의 하위 $p$ 비트에만 의존하므로 상위 비트의 구조를 모두 버린다.
- **2의 거듭제곱과 가깝지 않은 소수(prime)** 가 표준적 권장 사항이다 (CLRS §11.3).

> **균등성이 중요한 이유:** 모든 키가 같은 슬롯으로 해시되면 아무리 좋은 충돌 해결 기법도 결국 연결 리스트 순회로 퇴화한다. $O(1)$ 약속은 전적으로 해시 함수가 키를 균등하게 분산시킨다는 **가정** 에 기댄다 — 이것이 뒤에서 SUHA로 형식화된다.

### 1.5 충돌은 피할 수 없다

**충돌(collision)** 이란 서로 다른 두 키가 같은 해시 값을 만드는 것이다.

```
   Key: 25  ──►  h(25) = 5  ──┐
                              ├──►  Index 5  (충돌!)
   Key: 55  ──►  h(55) = 5  ──┘
```

**비둘기집 원리:** 키 공간은 일반적으로 인덱스 공간보다 훨씬 크다 ($|U| \gg m$). 따라서 개수만으로도 적어도 두 키는 같은 슬롯을 공유해야 한다.

심지어 $n \ll m$일 때조차 **생일 역설(birthday paradox)** 은 충돌이 직관보다 훨씬 빨리 발생함을 말해준다 — 무작위 키 약 $n \approx \sqrt{m}$개만 있으면 어떤 충돌이 발생할 확률이 이미 약 $1/2$이다.

따라서 실용적 질문은 "충돌을 어떻게 피할까?"가 아니라 "**충돌을 어떻게 효율적으로 해결할까?**"이다. 주요 전략은 두 가지다:

| 전략 | 다른 이름 | 아이디어 |
|------|----------|---------|
| 분리 연쇄법 (Separate Chaining) | Open Hashing | 충돌한 원소들의 연결 리스트 |
| 개방 주소법 (Open Addressing) | Closed Hashing | 다른 빈 슬롯을 찾는다 |

## 2. 충돌 해결

### 2.1 분리 연쇄법 (Open Hashing)

각 테이블 슬롯이 해당 인덱스로 해시된 모든 키-값 쌍의 **연결 리스트** 를 보관한다.

```
   Hash Table
   ┌───┬──────────────────────────────┐
   │ 0 │ → NULL                       │
   │ 1 │ → [11] → [21] → NULL         │
   │ 2 │ → [42] → NULL                │
   │ 3 │ → [13] → [33] → [73] → NULL  │
   │ 4 │ → NULL                       │
   │ 5 │ → [25] → [55] → NULL         │
   │ 6 │ → NULL                       │
   │ 7 │ → [37] → NULL                │
   │ 8 │ → NULL                       │
   │ 9 │ → [19] → NULL                │
   └───┴──────────────────────────────┘
```

**연산:**

| 연산 | 절차 | 비용 |
|------|------|------|
| `Insert(k)` | $h(k)$ 계산, 슬롯 $h(k)$ 리스트의 앞쪽에 추가 | $O(1)$ |
| `Search(k)` | $h(k)$ 계산, 슬롯 $h(k)$ 리스트를 순회 | $O(\text{체인 길이})$ |
| `Delete(k)` | 체인에서 $k$ 탐색 후 노드 분리 | $O(\text{체인 길이})$ |

### 2.2 분리 연쇄법 — 복잡도

**단순 균등 해싱 가정(Simple Uniform Hashing Assumption, SUHA):** 어떤 키든 다른 키와 독립적으로 $m$개의 슬롯 각각에 균등한 확률로 해시된다고 가정한다.

**부하율(load factor)** 을 다음과 같이 정의한다:

$$\alpha = \frac{n}{m} \quad \text{(슬롯당 저장된 키 수)}.$$

SUHA 하에서 각 체인의 **기댓값** 은 정확히 $\alpha$이다.

| 연산 | 평균 사례 | 최악 사례 |
|------|----------|----------|
| 탐색 (실패) | $\Theta(1 + \alpha)$ | $\Theta(n)$ |
| 탐색 (성공) | $\Theta(1 + \alpha)$ | $\Theta(n)$ |
| 삽입 | $O(1)$ | $O(1)$ |
| 삭제 | $\Theta(1 + \alpha)$ | $\Theta(n)$ |

$n = O(m)$ — 즉 $\alpha = O(1)$ — 을 유지하면 **모든 연산이 평균 $O(1)$** 이다.

> **최악 사례:** 모든 $n$개의 키가 같은 슬롯으로 해시된다. 테이블이 하나의 긴 연결 리스트로 퇴화하고 탐색이 $\Theta(n)$이 된다. 이것이 좋은 해시 함수와 재해싱(§3.2)이 중요한 이유다.

### 2.3 개방 주소법 (Closed Hashing)

모든 원소를 **테이블에 직접** 저장한다 — 연결 리스트 없음. 충돌이 발생하면 알고리즘이 다음 사용 가능한 슬롯을 **조사(probe)** 한다.

**일반 조사 수열:** $i = 0, 1, 2, \ldots, m-1$에 대해 $h(k, i)$.

**세 가지 표준 조사 전략:**

| 방법 | 아이디어 | 공식 |
|------|---------|------|
| 선형 조사 | 연속된 슬롯 확인 | $h(k,i) = (h'(k) + i) \bmod m$ |
| 이차 조사 | 이차 간격으로 확인 | $h(k,i) = (h'(k) + c_1 i + c_2 i^2) \bmod m$ |
| 이중 해싱 | 보조 해시 함수로 보폭 결정 | $h(k,i) = (h_1(k) + i \cdot h_2(k)) \bmod m$ |

여기서 $h'(k)$는 기본(단일) 해시 함수다.

### 2.4 선형 조사 — 예시

$h(k) = k \bmod 10$로 키 $\{25, 37, 42, 55, 73\}$을 크기 $m = 10$ 테이블에 삽입:

```
Step 1: Insert 25 → h(25)=5              Step 2: Insert 37 → h(37)=7
┌───┬────┐                               ┌───┬────┐
│ 5 │ 25 │                               │ 5 │ 25 │
│ 7 │    │                               │ 7 │ 37 │
└───┴────┘                               └───┴────┘

Step 3: Insert 42 → h(42)=2              Step 4: Insert 55 → h(55)=5
┌───┬────┐                               ┌───┬────┐
│ 2 │ 42 │                               │ 2 │ 42 │
│ 5 │ 25 │                               │ 5 │ 25 │ ← 차있음!
│ 7 │ 37 │                               │ 6 │ 55 │ ← 6번으로 조사
└───┴────┘                               │ 7 │ 37 │
                                         └───┴────┘

Step 5: Insert 73 → h(73)=3
┌───┬────┐
│ 2 │ 42 │
│ 3 │ 73 │
│ 5 │ 25 │
│ 6 │ 55 │
│ 7 │ 37 │
└───┴────┘
```

### 2.5 군집화 문제

선형 조사의 **일차 군집화(primary clustering):**

- 차있는 슬롯이 **긴 연속 블록(cluster)** 을 이루기 쉽다.
- 군집 어디로든 해시되는 새 키는 군집의 끝까지 조사해야 한다.
- 군집은 빈 영역보다 새 키를 더 빠르게 흡수한다 — 군집은 초선형적으로 자라며 성능을 악화시킨다.

```
   ┌───┬────┐
   │ 0 │    │
   │ 1 │    │
   │ 2 │ 42 │ ┐
   │ 3 │ 73 │ │ cluster
   │ 4 │ ?? │ │ (커지는 중)
   │ 5 │ 25 │ │
   │ 6 │ 55 │ ┘
   │ 7 │ 37 │
   │ 8 │    │
   │ 9 │    │
   └───┴────┘
```

- **이차 조사** 는 일차 군집화를 줄이지만 **이차 군집화** 를 일으킨다 — 처음 해시 값이 같은 키들은 여전히 동일한 조사 수열을 따른다.
- **이중 해싱** 은 가장 좋은 분산을 만들고 군집화를 거의 제거한다.

> **직관:** 군집화는 조사 경로가 *상관(correlated)* 되어 있을 때 발생한다. 선형 조사는 가까운 모든 키가 같은 경로를 공유하게 만든다. 이중 해싱은 키마다 보폭을 달리해 조사 수열의 상관을 끊는다.

### 2.6 이중 해싱

이중 해싱은 **두 개의** 해시 함수를 사용한다:

$$h(k, i) = (h_1(k) + i \cdot h_2(k)) \bmod m$$

- $h_1(k)$가 초기 슬롯을 결정한다.
- $h_2(k)$가 조사 사이의 **보폭(step size)** 을 결정한다.

**요구 조건:**
- 모든 키 $k$에 대해 $h_2(k) \neq 0$ (그렇지 않으면 제자리에서 무한 반복).
- $h_2(k)$가 $m$과 **서로소** 여야 한다 — 그래야 조사 수열이 반복 전에 모든 슬롯을 방문한다.

표준 레시피: $m$을 소수로 잡고 $h_2(k) = 1 + (k \bmod m')$, 단 $m' = m - 1$.

**예시** — $m = 7$, $h_1(k) = k \bmod 7$, $h_2(k) = 1 + (k \bmod 5)$:

| 키 $k$ | $h_1(k)$ | $h_2(k)$ | 조사 수열 |
|--------|----------|----------|----------|
| 15 | 1 | $1+(15 \bmod 5) = 1$ | 1, 2, 3, 4, 5, 6, 0 |
| 22 | 1 | $1+(22 \bmod 5) = 3$ | 1, 4, 0, 3, 6, 2, 5 |

두 키는 인덱스 1에서 충돌하지만 그 후로는 **서로 다른** 조사 경로를 따른다.

## 3. 성능 분석

### 3.1 부하율

**부하율** 은

$$\alpha = \frac{n}{m}.$$

| $\alpha$ 범위 | 의미 | 성능 |
|--------------|------|------|
| $\alpha < 0.5$ | 거의 비어 있음 | 매우 좋음 — $O(1)$에 근접 |
| $0.5 \leq \alpha < 0.75$ | 적당히 참 | 양호 — 수용 가능 |
| $\alpha \geq 0.75$ | 혼잡 | 저하 — 충돌 증가 |
| $\alpha = 1.0$ | 가득 참 (개방 주소법) | 매우 나쁨 — 조사 길이 폭증 |
| $\alpha > 1.0$ | 분리 연쇄법에서만 가능 | 체인이 길어짐 |

**경험칙:**
- 분리 연쇄법 — $\alpha \leq 1.0$ 유지.
- 개방 주소법 — $\alpha \leq 0.7$ 유지 (그 전에 크기 확장).

> **개방 주소법이 더 민감한 이유:** 분리 연쇄법에서 높은 $\alpha$는 단지 체인이 길어지는 것뿐이다. 개방 주소법에서는 균등 해싱 가정 하에 $\alpha \to 1$일 때 기대 조사 길이가 $\dfrac{1}{1-\alpha}$로 증가하며 빠르게 폭주한다.

### 3.2 재해싱

부하율이 임계치를 넘으면 **재해싱(rehashing)** — 즉 테이블 크기를 늘린다:

1. 크기 $m' \approx 2m$ 인 **새 테이블** 을 할당한다 (보통 $2m$ 직후의 소수).
2. 기존의 모든 키에 대해 새 테이블 크기로 $h(k)$를 **다시 계산** 한다.
3. 모든 원소를 새 테이블에 **재삽입** 한다.
4. 옛 테이블을 **해제** 한다.

```
   Old table (m=5, n=4, α=0.8)        New table (m=11, n=4, α≈0.36)
   ┌───┬────┐                          ┌────┬────┐
   │ 0 │ 25 │     rehash               │  0 │    │
   │ 1 │ 11 │   ─────────►             │  1 │ 11 │
   │ 2 │ 42 │                          │  2 │    │
   │ 3 │ 73 │                          │  3 │ 25 │
   │ 4 │    │                          │  4 │ 73 │
   └───┴────┘                          │  5 │    │
                                       │  6 │    │
                                       │  7 │ 42 │
                                       │  8 │    │
                                       │  9 │    │
                                       │ 10 │    │
                                       └────┴────┘
```

**비용:** 한 번의 재해싱은 $O(n)$이지만, 그것은 $\Theta(m)$번의 삽입마다 한 번씩만 일어난다. 긴 삽입 수열에 걸쳐 총 작업량이 한정되므로 삽입당 **분할상환 $O(1)$** 이 된다.

> **3주차와의 연결:** 이는 C++ `std::vector`나 Python `list`의 `push_back` / `append`에서 사용하는 두 배 확장(doubling) 논증과 동일하다. 이 동적 배열 분할상환 기법이 바로 해시 테이블이 가끔 $O(n)$ 재구축을 함에도 $O(1)$ 삽입을 주장할 수 있게 해주는 트릭이다.

### 3.3 해시 테이블 — 전체 복잡도

| 연산 | 평균 사례 | 최악 사례 |
|------|----------|----------|
| 탐색 | **$O(1)$** | $O(n)$ |
| 삽입 | **$O(1)$** 분할상환 | $O(n)$ |
| 삭제 | **$O(1)$** | $O(n)$ |

**왜 평균 $O(1)$인가?**
- SUHA 하에서 기대 체인(또는 조사) 길이는 $\Theta(1 + \alpha)$.
- 재해싱으로 $\alpha = O(1)$을 유지하므로 각 연산이 $O(1)$.

**$O(n)$ 최악 사례는 실제로 언제 나타나는가?**
- 너무 많은 키를 같은 슬롯으로 매핑하는 나쁜 해시 함수.
- 알려진 해시 함수를 악용하도록 만들어진 **적대적(adversarial)** 입력 — 웹 서버에서 실제로 문제가 된다 (hash-flooding DoS 공격을 참조; 많은 언어가 시작 시 해시 시드를 무작위화한다).

## 4. 집합, 사전, 그리고 비교

### 4.1 Set과 Map 자료구조

해시 테이블은 프로그래밍에서 가장 보편적인 두 추상 자료형의 기반이다:

**Set (집합)** — **중복 없는** 원소들의 모음.
- 연산: `add(x)`, `contains(x)`, `remove(x)` — 모두 평균 $O(1)$.
- 예: Python `set()`, Java `HashSet`, C++ `unordered_set`.

**Map (Dictionary, 사전)** — **키-값 쌍** 의 모음.
- 연산: `put(k, v)`, `get(k)`, `remove(k)` — 모두 평균 $O(1)$.
- 예: Python `dict`, Java `HashMap`, C++ `unordered_map`.

```python
# Python Set 예시                      # Python Dict (Map) 예시
visited = set()                        phone = {}
visited.add("A")                       phone["Alice"] = "010-1234"
visited.add("B")                       phone["Bob"]   = "010-5678"
visited.add("A")   # 중복!             print(phone["Alice"])  # O(1)
print(len(visited))    # 2             print("Bob" in phone)  # O(1)
print("A" in visited)  # True, O(1)
```

이들은 코딩 인터뷰와 경시 프로그래밍에서 가장 빈번하게 사용되는 자료구조에 속한다 — 많은 알고리즘 문제가 "올바른 Set/Map을 쓰자" 한 줄로 압축된다.

### 4.2 해시 테이블 vs BST — 언제 무엇을 쓸까

| 기준 | 해시 테이블 | 균형 BST (예: RBT — 9주차) |
|------|------------|---------------------------|
| 평균 탐색 | **$O(1)$** | $O(\log n)$ |
| 최악 탐색 | $O(n)$ | **$O(\log n)$** 보장 |
| 정렬된 순회 | 미지원 (또는 $O(n \log n)$) | **$O(n)$** in-order |
| 범위 질의 | 미지원 | **$O(\log n + k)$** |
| 메모리 오버헤드 | 배열 + 체인/조사 | 노드당 포인터 |
| 구현 | 좋은 해시 함수 필요 | 자가 균형 로직 |

**해시 테이블을 쓸 때:**
- **정확한** 키로 조회 / 삽입 / 삭제만 필요할 때.
- 최악 사례 보장보다 평균 $O(1)$이 더 중요할 때.

**균형 BST를 쓸 때:**
- **정렬된** 순회, **범위** 질의, 또는 최소/최대 연산이 필요할 때.
- **최악** $O(\log n)$ 보장이 필요할 때 (예: 실시간 시스템).

> **9주차와의 연결:** RBT와 B-Tree는 *순서* 를 강제한다. 해시 테이블은 직접 주소화의 대가로 순서를 버린다. 비용 모델 — *순서가 필요한가?* — 이 자료구조를 결정한다.

## 요약

| 개념 | 핵심 아이디어 | 비용 |
|------|--------------|------|
| 해시 함수 | 키 → 인덱스 매핑, $h(k) = k \bmod m$이 가장 단순 | $O(1)$ |
| 분리 연쇄법 | 슬롯마다 연결 리스트 | 평균 $\Theta(1 + \alpha)$, 최악 $\Theta(n)$ |
| 개방 주소법 | 다음 빈 슬롯 조사 (선형 / 이차 / 이중) | SUHA 하 평균 $\Theta(1/(1-\alpha))$ |
| 부하율 | $\alpha = n/m$이 기대 비용을 결정 | — |
| 재해싱 | $\alpha$ 임계 초과 시 테이블 두 배 확장 | 한 번 $O(n)$, 삽입당 **분할상환 $O(1)$** |
| Set / Map | "x가 있는가?" / "키 k의 값은?"에 대한 해시 기반 추상 | 평균 $O(1)$ |

**핵심 정리:**
- **해싱은 조회를 산술 연산으로 바꾼다** — $h(k)$가 인덱스를 주면 배열이 나머지를 처리한다.
- **충돌은 피할 수 없다** (비둘기집), 따라서 진짜 질문은 해결 전략이다.
- **분리 연쇄법** 은 단순하고 $\alpha > 1$도 견딘다. **개방 주소법** 은 캐시 친화적이지만 $\alpha \to 1$에서 무너진다.
- **군집화** 가 조사 기법의 주된 실패 모드 — 이중 해싱이 조사 수열의 상관을 끊어 대부분 해결한다.
- $O(1)$ 약속은 **SUHA 하 평균 사례** 다. 최악 사례는 $O(n)$이며 적대적 입력이 이를 유발할 수 있다 (따라서 무작위화된 해싱이 도입된다).
- 해시 테이블과 균형 BST는 상호 보완적이지 대체 가능한 것이 아니다 — 작업 부하가 **순서** 를 필요로 하는지에 따라 선택한다.

> "해시 테이블은 유한 매핑에다 '충돌은 드물 것'이라는 희망 섞인 가정을 더한 것이다."

## 점검 문제

1. **나눗셈법:** $h(k) = k \bmod m$에서 $m = 2^p$를 고르는 것이 왜 보통 나쁜 선택인가? 그 약점이 드러나는 키 집합을 구성하라.

   > **정답:** $k \bmod 2^p$는 $k$의 **하위 $p$ 비트** 에만 의존하므로 상위 비트의 구조를 모두 버린다. 키들이 공통된 하위 비트 패턴을 공유하면 모두 소수의 슬롯에 몰린다. **예시 $m = 8$:** 키 $\{8, 16, 24, 32, 40, 48, \ldots\}$은 모두 $\equiv 0 \pmod 8$이므로 슬롯의 수와 무관하게 전부 슬롯 0에 충돌한다. **2의 거듭제곱과 가깝지 않은 소수 $m$** 은 상위·하위 비트를 섞어 이런 함정을 피한다 (CLRS §11.3).

2. **비둘기집 / 생일 역설:** $m = 365$이고 임의의 키를 하나씩 삽입한다고 하자. *어떤* 충돌이 발생할 확률이 1/2를 넘기까지 몇 번의 삽입이 필요한가? 왜 이 값이 $m$보다 훨씬 작은가?

   > **정답:** 고전적인 **생일 역설** 의 답은 $n \approx 23$ — $m = 365$보다 훨씬 작다. 이유는 조합적이다: $n$번 삽입하면 키 **쌍** 의 수가 $\binom{n}{2} \approx n^2/2$개이고, 각 쌍이 충돌할 확률은 $1/m$이다. 기대 충돌 수가 1에 도달하는 시점은 $n \approx \sqrt{2m \ln 2} \approx \sqrt{m}$. "확률 1/2" 임계는 $\Theta(m)$이 아니라 $\Theta(\sqrt{m})$로 스케일된다 — 충돌은 직관보다 훨씬 빨리 발생한다.

3. **분리 연쇄법 복잡도:** 분리 연쇄법 해시 테이블이 $m = 250{,}000$개 슬롯에 $n = 10^6$개의 키를 보관한다. SUHA 하에서 실패 탐색의 기대 시간은? 성공 탐색의 기대 시간은?

   > **정답:** 부하율 $\alpha = n/m = 10^6 / 250{,}000 = 4$. **SUHA** 하에서 기대 체인 길이는 정확히 $\alpha$이므로, **실패 탐색** 은 평균적으로 체인 전체를 훑어 $\Theta(1 + \alpha) = \Theta(5)$ 비교 — 해시 계산 1회 + 리스트 노드 방문 4회. **성공 탐색** 은 평균적으로 체인의 절반만 보면 되어 $\Theta(1 + \alpha/2) = \Theta(3)$ 비교. $\alpha$ 측면에선 $O(1)$이지만 상수 인자가 무시 못 할 수준이므로 보통 $\alpha \leq 1$을 유지한다.

4. **선형 조사 추적:** $h(k) = k \bmod 10$, 선형 조사, $m = 10$ 테이블에 $\{4, 14, 24, 25, 35\}$를 삽입하라. 최종 테이블을 그리고 각 삽입에서의 조사 횟수를 보고하라.

   > **정답:** $h(4) = 4$ → 슬롯 4 배치 (**조사 1회**). $h(14) = 4$ → 슬롯 4 차있음, 5 시도 → 슬롯 5 배치 (**조사 2회**). $h(24) = 4$ → 4, 5 차있음, 6 시도 → 슬롯 6 배치 (**조사 3회**). $h(25) = 5$ → 5, 6 차있음, 7 시도 → 슬롯 7 배치 (**조사 3회**). $h(35) = 5$ → 5, 6, 7 차있음, 8 시도 → 슬롯 8 배치 (**조사 4회**). 최종: 슬롯 4=4, 5=14, 6=24, 7=25, 8=35 — 길이 5의 **일차 군집** 이 형성되어 군집화 현상을 보여준다.

5. **이중 해싱 경로:** $m = 11$, $h_1(k) = k \bmod 11$, $h_2(k) = 1 + (k \bmod 9)$일 때, 키 $k = 22$와 $k = 33$의 첫 네 조사 위치를 나열하라. 두 수열이 같은 슬롯을 다시 방문하는가?

   > **정답:** $k = 22$: $h_1 = 0$, $h_2 = 1 + 4 = 5$ → 조사 위치 **0, 5, 10, 4** (각 단계 `+5 mod 11`). $k = 33$: $h_1 = 0$, $h_2 = 1 + 6 = 7$ → 조사 위치 **0, 7, 3, 10**. 슬롯 0에서 처음 **충돌** 하고 슬롯 10도 서로 다른 조사 단계에서($i=2$가 22, $i=3$이 33) **재방문** 하지만 전체 조사 수열은 다르다 — 두 **보폭**(5와 7)이 초기 충돌 이후 경로의 상관을 끊는다. 이것이 바로 군집화를 없애는 핵심이다.

6. **부하율과 조사 길이:** 개방 주소법 + 균등 해싱 하에서 실패 탐색의 기대 조사 횟수가 $E[\text{probes}] \leq \dfrac{1}{1-\alpha}$임을 유도(또는 인용)하라. $\alpha \to 1$이면 무슨 일이 일어나는가? 크기 확장 임계치에 대해 무엇을 의미하는가?

   > **정답:** **균등 해싱** 하에서 첫 조사가 차있는 슬롯에 떨어질 확률은 $\alpha = n/m$. 그 조건 하에서 두 번째 조사가 차있을 확률은 $\approx (n-1)/(m-1) \leq \alpha$, 이런 식으로 계속된다. 기대 조사 횟수는 $\sum_{i \geq 0} \alpha^i = \dfrac{1}{1 - \alpha}$ (기하급수). $\alpha \to 1$이면 **무한대로 발산** 한다 — $\alpha = 0.9$에서 기대 조사 10회, $\alpha = 0.99$에서 100회. 실용 규칙: 개방 주소법은 **$\alpha \approx 0.7$ 전에 크기 확장** 하여 기대 조사를 3.3회 이하로 유지한다.

7. **재해싱 분할상환:** $\alpha > 0.75$이 되면 테이블을 두 배로 늘린다고 할 때, $n$번의 삽입 총비용이 $O(n)$임을 보여라. 함의된 분할상환 논증을 명시적으로 진술하라.

   > **정답:** 재해싱은 크기 $m_0, 2m_0, 4m_0, \ldots$에서 발생하며 각각 $\Theta(m_i)$의 비용으로 모든 키를 재삽입한다. 총 재해싱 비용은 $\Theta(m_0 + 2m_0 + 4m_0 + \cdots + n) = \Theta(2n) = O(n)$ — 마지막 항이 지배하는 **기하급수**. 여기에 $n$번의 단순 $O(1)$ 삽입을 더해도 총합은 $O(n)$이므로 **삽입당 분할상환 $O(1)$**. **회계 논증(accounting)**: 각 삽입에 $O(1)$의 추가 "크레딧"을 부과하고, 테이블이 두 배로 늘 때 누적된 크레딧으로 대량 재삽입 비용을 지불한다. `std::vector::push_back`과 Python `list.append`도 정확히 같은 기법을 쓴다.

8. **해시 테이블 vs BST:** 다음 작업 부하 각각에 대해 해시 테이블과 균형 BST 중 하나를 선택하고 한 문장으로 정당화하라.
   (a) "이 단어가 사전에 있는가?"를 묻는 맞춤법 검사기.
   (b) 주어진 접두사로 시작하는 모든 단어를 반환하는 자동 완성 서비스.
   (c) 항상 점수 순으로 순회 가능해야 하는 리더보드.
   (d) 최악 $O(\log n)$ 조회가 필요한 실시간 컨트롤러.

   > **정답:** **(a) 해시 테이블** — 정확한 일치 여부만 묻기 때문에 평균 $O(1)$이 압도적으로 유리하다. **(b) BST (또는 trie)** — 접두사 질의는 **정렬된 순회** 가 필요한데 해시 테이블은 이를 효율적으로 지원하지 못한다. **(c) BST** — 중위 순회가 점수 순서를 그대로 내놓아야 하는데, 이것이 바로 해시 테이블이 포기한 연산이다. **(d) BST (RBT)** — 실시간 시스템은 **최악 $O(\log n)$** 을 요구하지만 해시 테이블은 나쁜 입력에서 $O(n)$으로 떨어진다.

9. **적대적 입력:** 웹 프레임워크가 사용자가 보낸 문자열을 고정 테이블에 해시한다. 공격자가 어떻게 요청당 성능을 $O(n)$으로 떨어뜨릴 수 있는지, 그리고 무작위화(시드) 해싱이 어떻게 공격을 완화하는지 설명하라.

   > **정답:** 해시 함수가 **결정적이고 공개되어 있다면**(예: 고정된 시드), 공격자는 같은 슬롯으로 해시되는 문자열을 사전 계산해 POST 파라미터로 한꺼번에 보낼 수 있다. 모든 키가 한 체인에 몰려 삽입마다 $O(n)$ 리스트 순회가 발생한다 — 2011년경 PHP·Java·Python을 모두 마비시킨 **hash-flooding DoS** 공격. **무작위화 해싱** 은 **프로세스 시작 시 비밀 시드** 를 선택하므로 공격자가 특정 서버용 충돌 키를 사전 계산할 수 없다. 무작위 키를 쓴 SipHash가 Python·Ruby·Rust에서 채택한 현대 표준이다.

10. **개방 주소법 삭제:** 개방 주소법에서 단순히 슬롯을 "비우는" 것이 왜 위험한가? 조사 체인 정확성을 보존하기 위한 **묘비(tombstone)** 표식 기법을 설명하라.

    > **정답:** 개방 주소법의 탐색 규칙은 "키가 있었다면 조사 수열에서 그보다 앞에 배치되었을 것"이라는 가정 하에 **첫 번째 빈 슬롯에서 멈춘다**. 조사 체인 중간의 슬롯을 비우면, 그 뒤에 조사로 배치되었던 모든 키가 **도달 불가능** 해진다 — 탐색이 빈 곳에서 멈춰 키를 못 찾는다. **묘비** 기법은 그 슬롯을 "삭제됨, 그러나 이전에 점유됨"으로 표시한다: 탐색은 그것을 **차있는 것처럼** 취급해 계속 조사하고, 삽입은 **빈 것처럼** 취급해 재사용할 수 있다. 묘비는 시간이 지나며 쌓이므로 주기적인 재해싱으로 정리해야 한다.
