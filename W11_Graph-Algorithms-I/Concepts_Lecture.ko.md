> 8. 그래프의 밀도와 간선/정점 접근 패턴에 따라 적절한 알고리즘과 표현을 선택할 수 있다

## 1. 그래프 기초와 표현

### 1.1 그래프란?

**그래프(graph)** 는 객체 사이의 관계를 **정점(vertex)** 과 **간선(edge)** 으로 모델링한다.

- $G = (V, E)$
  - $V$: **정점(노드)** 의 집합
  - $E$: **간선(연결)** 의 집합
- 간선으로 연결된 두 정점을 **인접(adjacent)** 하다고 한다.

```
     1 --- 2
     |   / |
     |  /  |
     | /   |
     3 --- 4
```

**응용:** 소셜 네트워크, 도로 지도, 회로 설계, 웹 하이퍼링크, 빌드 의존성, 작업 스케줄링, 생물학적 경로 등.

> **그래프가 특별한 이유:** 배열이나 트리와 달리 그래프는 내장된 "다음"이나 "부모"가 없다. 그래프를 알고리즘적으로 다루려면 먼저 *표현 방식* 을 골라야 한다. 이 선택(행렬 vs 리스트)이 이후 모든 것의 복잡도를 결정한다.

### 1.2 그래프의 유형

| 유형 | 설명 | 예시 |
|------|------|------|
| **무방향(Undirected)** | 간선에 방향이 없음 | 친구 관계 |
| **방향(Directed, Digraph)** | 간선에 방향(화살표)이 있음 | 웹 하이퍼링크, 선수 과목 |
| **가중치(Weighted)** | 간선에 수치 가중치 | 도로 거리, 비용 |
| **무가중치(Unweighted)** | 모든 간선이 동등 | 단순 연결성 |

```
Undirected:          Directed:           Weighted:
  1 --- 2            1 --> 2             1 --5-- 2
  |     |            |     ^             |       |
  3 --- 4            v     |             3       7
                     3 --> 4             |       |
                                         3 --2-- 4
```

### 1.3 인접 행렬

$N \times N$ 행렬 사용 ($N = |V|$):

- 원소 $(i, j)$ = 간선이 있으면 **1**, 없으면 **0**.
- **방향 그래프** 의 경우 $(i, j)$는 $i$에서 $j$로 가는 간선을 의미한다 — 따라서 행렬은 일반적으로 **비대칭** 이다.
- **가중치 그래프** 의 경우 1 대신 **가중치** 를 저장한다.

```
Graph:             인접 행렬:
   1 --- 2              1  2  3  4
   |   / |          1 [ 0  1  1  0 ]
   |  /  |          2 [ 1  0  1  1 ]
   | /   |          3 [ 1  1  0  1 ]
   3 --- 4          4 [ 0  1  1  0 ]
```

### 1.4 인접 행렬 — 방향 그래프와 가중치 그래프 예시

**방향 그래프** — 행렬이 대칭이 아니다:

```
방향 그래프:               인접 행렬:
   1 --> 2                    1  2  3  4
   |     ^                1 [ 0  1  1  0 ]
   v     |                2 [ 0  0  0  0 ]
   3 --> 4                3 [ 0  0  0  1 ]
                          4 [ 0  1  0  0 ]
```

**가중치 그래프** — 행렬이 가중치를 담는다 (간선이 없음을 표현할 때 관례에 따라 $0$ 또는 $\infty$ 사용):

```
가중치 그래프:             인접 행렬:
   1 --5-- 2                  1   2   3   4
   |       |              1 [ 0   5   3   0 ]
   3       7              2 [ 5   0   0   7 ]
   |       |              3 [ 3   0   0   2 ]
   3 --2-- 4              4 [ 0   7   2   0 ]
```

### 1.5 인접 행렬 — 분석

**장점:**
- 이해하고 구현하기 쉽다.
- 간선 $(i, j)$ 존재 여부를 **$O(1)$** 에 확인할 수 있다.

**단점:**
- 항상 **$O(N^2)$** 공간 — 간선이 매우 적어도 마찬가지.
- 초기화만 해도 $\Theta(N^2)$.
- **희소(sparse)** 그래프에는 낭비가 심하다.

**예시:** $10^6$개 정점, $2 \cdot 10^6$개 간선
- 행렬은 $10^{12}$개의 원소를 갖지만 그중 단 $2 \cdot 10^6$개만 0이 아니다.

> **적합한 경우:** 대부분의 정점 쌍이 연결된 **밀집(dense)** 그래프 — 어차피 행렬 칸 대부분이 채워질 것이기 때문.

### 1.6 인접 리스트

**$N$개의 연결 리스트** 를 사용한다 (정점당 하나). $i$번째 리스트는 정점 $i$에 인접한 모든 정점을 담는다. 가중치 그래프에서는 각 노드가 간선 가중치도 함께 저장한다.

```
Graph:                인접 리스트:
   1 --- 2            1: [2] -> [3]
   |   / |            2: [1] -> [3] -> [4]
   |  /  |            3: [1] -> [2] -> [4]
   | /   |            4: [2] -> [3]
   3 --- 4
```

**가중치 버전** — `(이웃, 가중치)` 쌍을 저장:

```
가중치 그래프:        인접 리스트 (정점, 가중치):
   1 --5-- 2          1: [(2,5)] -> [(3,3)]
   |       |          2: [(1,5)] -> [(4,7)]
   3       7          3: [(1,3)] -> [(4,2)]
   |       |          4: [(2,7)] -> [(3,2)]
   3 --2-- 4
```

### 1.7 인접 리스트 — 분석

**장점:**
- 간선에 비례하는 공간: **$O(V + E)$**.
- 낭비되는 슬롯이 없음 — 간선이 적을 때 이상적.
- 한 정점의 이웃을 순회할 때 효율적.

**단점:**
- 간선 존재 질의 $(i, j)$의 비용이 $O(\deg(i))$ — $O(1)$이 아님.
- 매우 밀집한 그래프에서는 포인터 추적으로 캐시 성능이 떨어질 수 있다.

> **적합한 경우:** $E \ll V^2$인 **희소** 그래프 — 대부분의 현실 그래프(소셜 네트워크, 도로 지도, 웹 링크)가 여기 해당된다.

### 1.8 인접 배열

각 정점의 연결 리스트를 **배열** 로 바꾸거나, 인덱스 테이블과 함께 **하나의 연속된 배열** 에 모두 패킹한다.

```
정점별 배열:              패킹된 배열 형태:
   Vertex:  1    2    3    4
   Count:  [2]  [2]  [3]  [2]
                                A = [2,3 | 1,3,4 | 1,2,4 | 2,3]
   1: [2, 3]                    Index: [0, 2, 5, 8, 10]
   2: [1, 3, 4]
   3: [1, 2, 4]
   4: [2, 3]
```

**연결 리스트 기반 인접에 비한 장점:**
- 포인터 오버헤드 없음 — 캐시 친화적.
- 이웃이 정렬되어 있으면 이진 탐색으로 간선 존재 여부를 **$O(\log \deg)$** 에 확인할 수 있다.
- 성능 임계 환경(그래프 데이터베이스, GPU 작업)의 *정적* 그래프에 표준적으로 사용된다.

### 1.9 표현 방식 비교

| | 인접 행렬 | 인접 리스트 | 인접 배열 |
|---|----------|------------|----------|
| **공간** | $O(V^2)$ | $O(V + E)$ | $O(V + E)$ |
| **간선 조회** | $O(1)$ | $O(\deg)$ | $O(\log \deg)$ |
| **이웃 순회** | $O(V)$ | $O(\deg)$ | $O(\deg)$ |
| **간선 추가** | $O(1)$ | $O(1)$ | $O(\deg)$ (재구성) |
| **적합한 경우** | 밀집 그래프 | 희소 그래프 | 희소, 정적 그래프 |

> 실제로는 **인접 리스트** (또는 배열)가 기본 선택이다. 대부분의 현실 그래프가 희소하기 때문. 행렬은 $E$가 $V^2$에 근접하거나 상수 시간 간선 질의가 작업의 대부분일 때만 우위를 점한다.

## 2. 그래프 순회 — BFS와 DFS

### 2.1 모든 정점 방문

모든 정점을 체계적으로 방문하는 두 가지 근본적 방법:

| | **BFS** (너비 우선 탐색) | **DFS** (깊이 우선 탐색) |
|---|--------------------------|--------------------------|
| **전략** | 레벨 단위 방문 | 가능한 한 깊이 먼저 |
| **자료구조** | 큐 (FIFO) | 스택 / 재귀 (LIFO) |
| **시간 복잡도** | $O(V + E)$ | $O(V + E)$ |

```
         1
        /|\
       2  3  4
      /|     |
     5  6    7

BFS from 1: 1 -> 2, 3, 4 -> 5, 6, 7
DFS from 1: 1 -> 2 -> 5 -> 6 -> 3 -> 4 -> 7
```

> BFS와 DFS는 거의 모든 그래프 알고리즘의 **토대** 다. 연결 요소, 사이클 탐지, 위상 정렬, 최단 홉 경로, SCC 분해 — 모두 이 둘 중 하나에 약간의 부기(bookkeeping)를 더한 것이다.

### 2.2 DFS — 알고리즘

```
DFS(G)
    for each v in V
        visited[v] <- NO
    for each v in V
        if visited[v] = NO then aDFS(v)

aDFS(v)
    visited[v] <- YES                    ... (A)
    for each x in L(v)                   ... (B)
        if visited[x] = NO then aDFS(x)  ... (C)
```

- **(A)** $v$를 방문 표시 — 모든 호출에 걸쳐 $|V|$번 일어남 → **$O(V)$**.
- **(B)** $v$의 인접 리스트 스캔.
- **(C)** 미방문일 때만 재귀. 각 간선은 최대 두 번 확인된다 (무방향 그래프에서 각 끝점에서 한 번씩). 따라서 (B)/(C) 라인의 총 작업량은 **$O(E)$**.

**총 시간: $O(V + E)$.**

> **"$V+E$에 선형"이 옳은 척도인 이유:** 모든 정점과 간선을 적어도 한 번씩 보아야 하는 어떤 알고리즘이든 $\Omega(V + E)$를 지불해야 한다. DFS는 이 하한에 도달하므로 "모든 정점을 보기" 작업에 점근적으로 최적이다.

### 2.3 DFS — 단계별 예시

```
Graph:                    인접 리스트:
   1 --- 2                1: [2, 3, 4, 6]
   |   / | \              2: [1, 3]
   |  /  |  6             3: [1, 2, 5]
   | /   |                4: [1, 6]
   3     5                5: [3, 6]
   |   /                  6: [1, 4, 5]
   4 - 6
```

```
정점 1에서 시작하는 DFS:
Step 1: 1 방문, 이웃 2로 이동
Step 2: 2 방문, 이웃 3으로 이동
Step 3: 3 방문, 이웃 5로 이동
Step 4: 5 방문, 이웃 6으로 이동
Step 5: 6 방문, 이웃 4로 이동
Step 6: 4 방문, 백트래킹

순회: 1 → 2 → 3 → 5 → 6 → 4
```

### 2.4 DFS — 상세 추적

```
호출 스택 추적:

aDFS(1)                     visited: {1}
  aDFS(2)                   visited: {1,2}
    aDFS(3)                 visited: {1,2,3}
      aDFS(5)               visited: {1,2,3,5}
        aDFS(6)             visited: {1,2,3,5,6}
          aDFS(4)           visited: {1,2,3,5,6,4}
            neighbors: 1(visited), 6(visited)
            -> return
          -> return
        -> return
      -> return
    -> return
  -> return
```

각 정점은 **정확히 한 번** 방문되고, 각 간선은 **최대 두 번** 확인된다.

### 2.5 BFS — 알고리즘

```
BFS(G, s)
    for each v in V - {s}
        visited[v] <- NO
    visited[s] <- YES
    enqueue(Q, s)                       ... (A)
    while Q is not empty
        u <- dequeue(Q)                 ... (A)
        for each v in L(u)              ... (B)
            if visited[v] = NO then
                visited[v] <- YES
                enqueue(Q, v)
```

- **(A)** 각 정점은 큐에 정확히 한 번씩 들어가고 나간다 → **$O(V)$**.
- **(B)** 각 인접 리스트는 한 번 스캔된다 → **$O(E)$**.

**총 시간: $O(V + E)$.**

### 2.6 BFS — 단계별 예시

```
Graph:                    인접 리스트:
   1 --- 2                1: [2, 3, 4, 6]
   |   / | \              2: [1, 3]
   |  /  |  6             3: [1, 2, 5]
   | /   |                4: [1, 6]
   3     5                5: [3, 6]
   |   /                  6: [1, 4, 5]
   4 - 6
```

```
정점 1에서 시작하는 BFS:

Step 1: 1 dequeue.  이웃 방문: 2, 3, 4, 6
        Queue: [2, 3, 4, 6]       Level 0: {1}

Step 2: 2 dequeue.  이웃 1(방문), 3(방문) → skip
        Queue: [3, 4, 6]          Level 1: {2, 3, 4, 6}

Step 3: 3 dequeue.  이웃 5 미방문 → enqueue
        Queue: [4, 6, 5]

Step 4: 4 dequeue.  모든 이웃 방문 → skip
        Queue: [6, 5]

Step 5: 6 dequeue.  모든 이웃 방문 → skip
        Queue: [5]

Step 6: 5 dequeue.  모든 이웃 방문 → skip
        Queue: []                 Level 2: {5}

순회 순서: 1 → 2 → 3 → 4 → 6 → 5
```

### 2.7 BFS는 최단 홉 수 경로를 준다

정점 1에서 시작하면 BFS는 자연스럽게 **레벨 단위로** 정점을 발견한다:

```
Level 0: {1}           ← 시작점에서 0 홉
Level 1: {2, 3, 4, 6}  ← 시작점에서 1 홉
Level 2: {5}           ← 시작점에서 2 홉
```

> **무가중치** 그래프에서 BFS는 시작 정점에서 도달 가능한 모든 정점까지의 **최단 경로** (최소 간선 수)를 찾는다.

**증명 개요:** 레벨 $\ell$에 대한 귀납. 정점 $v$를 처음 발견할 때 부모는 레벨 $\ell - 1$에 있고, 더 짧은 경로가 있었다면 $v$가 더 일찍 도달되었을 것 — 모순. 큐의 "FIFO" 규율이 바로 "레벨 $\ell - 1$이 레벨 $\ell$보다 먼저"를 강제한다.

이 최단 경로 성질은 **가중치 그래프** 에서는 일반화되지 않는다 — 그때는 Dijkstra(5주차 / 12주차)가 필요하다.

### 2.8 BFS vs DFS — 비교

| 성질 | BFS | DFS |
|------|-----|-----|
| **자료구조** | 큐 (FIFO) | 스택 / 재귀 (LIFO) |
| **순서** | 레벨 단위 | 가능한 한 깊이 |
| **최단 경로** | 예 (무가중치) | 아니오 |
| **메모리** | 큐를 위한 $O(V)$ (최악 폭) | 재귀 스택을 위한 $O(V)$ (최악 깊이) |
| **시간** | $O(V + E)$ | $O(V + E)$ |
| **흔한 용도** | 최단 홉 경로, 레벨별 처리, 홉 제한 웹 크롤링 | 위상 정렬, 사이클 탐지, SCC(Tarjan/Kosaraju), 미로 풀이 |

두 알고리즘 모두 동일한 점근적 시간을 갖지만 그래프를 탐색하는 순서가 근본적으로 다르다.

## 3. 위상 정렬

### 3.1 위상 정렬 — 정의

**전제 조건:** 방향 비순환 그래프(DAG) — 방향 사이클이 없음.

**정의:** 모든 방향 간선 $(x, y)$에 대해 $x$가 $y$보다 **앞** 에 오도록 모든 정점을 선형으로 나열한다.

- 같은 DAG에 대해 여러 유효한 순서가 존재할 수 있다.
- 그래프가 위상 정렬을 가질 수 있는 **필요충분조건** 은 그래프가 DAG인 것이다.

```
DAG:
   A --> B --> D
   |          ^
   v         /
   C -------

위상 순서:
   A, B, C, D    (유효)
   A, C, B, D    (유효)
```

> **용례:** 강의 선수 과목, 빌드 시스템 (예: `make`, `ninja`), 패키지 매니저, 요리 단계, 스프레드시트 재계산 순서.

### 3.2 알고리즘 1 — In-Degree 방법

```
topologicalSort1(G)
    for i ← 1 to n
        in-degree가 0인 정점 u 선택
        A[i] ← u
        그래프에서 정점 u와 그것의 모든 나가는 간선 제거
    // A[1..n]이 위상 순서를 담는다
```

**동작 원리:** in-degree가 0인 정점이면 그 앞에 와야 할 정점이 없으므로 다음에 배치해도 안전하다. 그 정점을 제거하면 다른 정점의 in-degree만 줄어드므로 성질이 유지된다.

**구현 팁:** `in_degree[]` 배열과 in-degree 0인 정점들의 큐를 유지하면 알고리즘이 BFS와 비슷한 형태가 되어 **$O(V + E)$** 로 동작한다 (Kahn 알고리즘이라고도 부른다).

```
예시 (라면 레시피):

Step (a): "봉지 뜯기"가 in-degree 0 → 선택, 간선 제거
Step (b): "물 끓이기"가 in-degree 0 → 선택, 간선 제거
Step (c): "면 넣기"가 in-degree 0 → 선택, 간선 제거
   …모든 정점이 배치될 때까지 반복
```

### 3.3 알고리즘 2 — DFS 기반 방법

```
topologicalSort2(G)
    for each v in V
        visited[v] ← NO
    for each v in V
        if visited[v] = NO then DFS-TS(v)

DFS-TS(v)
    visited[v] ← YES
    for each x in L(v)
        if visited[x] = NO then DFS-TS(x)
    v를 연결 리스트 R의 맨 앞에 삽입    // 모든 자식 방문 후
```

- DFS가 한 정점을 끝낼 때 (모든 후손이 끝나면), 결과 리스트 $R$의 **앞쪽에** 그 정점을 추가한다.
- 알고리즘이 종료되면 $R$이 위상 순서다.

**시간 복잡도: $O(V + E)$** (DFS와 동일).

> **왜 끝날 때 앞에 삽입하는가?** 한 정점은 그것에서 도달 가능한 모든 후손이 이미 $R$에 들어가 있을 때에만 "끝났다". 방금 끝난 정점을 $R$의 맨 앞에 두면, 그 정점이 자신으로부터 도달 가능한 모든 정점보다 앞에 오게 된다 — 이것이 정확히 위상 순서가 요구하는 것이다.

### 3.4 DFS 위상 정렬 — 예시

```
DAG:
   A --> B --> D
   |          ^
   v         /
   C -------

A에서 DFS-TS:
   A 방문 → B 방문 → D 방문
     D 끝   → R = [D]
     B 끝   → R = [B, D]
   C 방문
     D 이미 방문 → R = [C, B, D]
   A 끝       → R = [A, C, B, D]

결과: A → C → B → D ✓
```

핵심: 정점은 그것에서 도달 가능한 모든 정점이 이미 기록된 **후에야** 앞에 추가된다.

## 4. 최소 신장 트리 (MST)

### 4.1 MST — 개념과 동기

**전제 조건:**
- **연결** 그래프 — 모든 정점 쌍 사이에 경로가 존재.
- **무방향**, **가중치** 간선.

**트리:**
- 사이클이 **없는** 연결 그래프.
- $n$개 정점의 트리는 **정확히 $n - 1$개의 간선** 을 가진다.

**$G$의 신장 트리:**
- $G$의 **모든 정점** 을 포함하고 $G$의 간선만 사용하는 트리인 부분 그래프.

**최소 신장 트리(MST):**
- $G$의 모든 신장 트리 중 **간선 가중치 총합이 최소** 인 것.

```
문제: 최소 도로 비용으로 모든 도시를 연결하라.

   도시 (정점):            목표: 가장 적고 저렴한 도로로
     A --5-- B                   모든 도시를 연결
     |\ /|                  
     | X  |                  MST = 그래프를 연결 상태로 유지하면서
     |/ \|                         가중치 총합 최소인 n-1개의
     C --3-- D                     간선을 선택
```

> **놀라운 사실:** MST는 **그리디** 알고리즘이 증명적으로 최적인 몇 안 되는 최적화 문제 중 하나다. 그리디 선택의 정당화는 **컷 성질(cut property)** 이다 — $V$를 $(S, V \setminus S)$로 분할한 임의의 컷에서 최소 가중치 간선은 *어떤* MST에 속한다. Prim과 Kruskal은 이 성질을 적용하는 두 가지 다른 방법일 뿐이다.

### 4.2 Prim 알고리즘 — 아이디어

**전략:** 하나의 루트에서 시작해 MST를 정점 단위로 키운다.

```
Prim(G, r)
    S ← empty set
    정점 r 방문 표시; S에 r 추가
    while S ≠ V
        S와 V - S를 잇는 최소 가중치 간선 (x, y) 찾기 (x ∈ S, y ∈ V - S)
        y 방문 표시; S에 y 추가
```

- 매 단계, **컷 $(S, V \setminus S)$을 건너는 가장 싼 간선** 을 고른다 — 전형적 그리디 선택.
- 이진 힙으로 minimum 추출: **$O(E \log V)$**.
- 피보나치 힙 사용: $O(E + V \log V)$ — 밀집 그래프에 이론적으로 더 좋음.

### 4.3 Prim 알고리즘 — 상세 의사코드

```
Prim(G, r)                            // G = (V, E), r = 시작 정점
    S ← empty
    for each u in V
        d[u] ← ∞                      // (1) 거리 초기화
    d[r] ← 0                          // (2) 시작 정점 거리 = 0
    while S ≠ V                       // (3) |V|번 반복
        u ← extractMin(V - S, d)      // (4) 가장 가까운 fringe 정점
        S ← S ∪ {u}                   // (5) MST 집합에 추가
        for each v in L(u)            // (6) 이웃 relax
            if v in V - S and w(u, v) < d[v] then
                d[v] ← w(u, v)        // (7) 더 싼 연결로 갱신
                tree[v] ← u           // MST의 부모 기록
```

- **extractMin** 은 힙 사용 → 추출당 $O(\log V)$, 총 $V$회 추출 → $O(V \log V)$.
- **Relaxation** (라인 7) — $S$에서 $v$로 가는 더 싼 간선이 있으면 $d[v]$ 갱신. 모든 반복에 걸친 모든 이웃에 대해 $O(E \log V)$ (각 간선은 최대 한 번의 decrease-key를 유발).
- **총: $O(E \log V)$.**

### 4.4 Prim 알고리즘 — 풀이 예시

```
가중치 그래프:
         8
     A -------- B
     |\        /|
     | \5   9/  |
    3|  \  /   7|
     |   \/     |
     |   /\     |
     |  /  \    |
     | /  2 \   |
     C--------D
        |   /
       4|  /6
        | /
        E

Edges: (A,B,8) (A,C,3) (A,D,5) (B,D,9) (B,E,7) (C,D,2) (C,E,4) (D,E,6)
```

**실행 추적 (A에서 시작):**

```
Step 0: S={A}     d: A=0, B=∞, C=∞, D=∞, E=∞
        A에서 relax: d[B]=8, d[C]=3, d[D]=5

Step 1: extractMin → C (d=3).  S={A, C}
        C에서 relax: d[D] = min(5,2) = 2,  d[E] = 4
        MST 간선: A—C  (가중치 3)

Step 2: extractMin → D (d=2).  S={A, C, D}
        D에서 relax: d[B] = min(8,9) = 8 (변경 없음),  d[E] = min(4,6) = 4 (변경 없음)
        MST 간선: C—D  (가중치 2)

Step 3: extractMin → E (d=4).  S={A, C, D, E}
        E에서 relax: d[B] = min(8,7) = 7
        MST 간선: C—E  (가중치 4)

Step 4: extractMin → B (d=7).  S={A, C, D, E, B}
        MST 간선: E—B  (가중치 7)

MST 가중치 총합: 3 + 2 + 4 + 7 = 16
```

**결과 MST:**

```
   MST (가중치 = 16):
     A         B
     |         |
     |3        |7
     |         |
     C         |
     |\        |
     | \2      |
     |  D      |
     |
    4|
     |
     E

MST 간선: A-C(3), C-D(2), C-E(4), E-B(7)
```

### 4.5 Kruskal 알고리즘 — 아이디어

**전략:** 모든 간선을 가중치 순으로 정렬한다. 가장 싼 간선을 차례로 추가하되, 사이클을 만드는 간선은 건너뛴다.

```
Kruskal(G)
    T ← empty set                       // MST 간선
    n개의 singleton 집합 생성 (정점당 하나)
    모든 간선 Q를 가중치 오름차순으로 정렬
    while |T| < n - 1
        Q에서 최소 가중치 간선 (u, v) 추출
        if u와 v가 서로 다른 집합에 있으면
            두 집합 Union
            T ← T ∪ {(u, v)}
```

- **사이클 탐지** 는 **Union-Find(Disjoint Set)** 자료구조 사용.
  - `Find(x)` — $x$가 어떤 컴포넌트에 속하는가? — 경로 압축 시 $O(\alpha(V))$ amortized.
  - `Union(x, y)` — 두 컴포넌트 병합 — union-by-rank 시 $O(\alpha(V))$ amortized.
- 간선 정렬: $O(E \log E) = O(E \log V)$ ($E \leq V^2$이므로).

**총 시간: $O(E \log V)$.**

> **Union-Find 입문:** 각 컴포넌트를 부모 포인터 트리로 유지한다. `Find`는 루트까지 따라가고, `Union`은 한 루트를 다른 루트 아래에 연결한다. 경로 압축은 `Find` 도중 트리를 평탄화하고, union-by-rank는 더 짧은 트리를 더 큰 트리 아래에 연결한다. 둘을 합치면 거의 선형인 역 Ackermann 인자 $\alpha(V)$를 얻는데, 이는 상상할 수 있는 모든 $V$에 대해 $\leq 4$이다.

### 4.6 Kruskal 알고리즘 — 풀이 예시

```
가중치 순 정렬된 간선:
   (C,D,2), (A,C,3), (C,E,4), (A,D,5), (D,E,6), (B,E,7), (A,B,8), (B,D,9)

초기 집합: {A}, {B}, {C}, {D}, {E}
```

```
Step 1: 간선 (C,D,2) — C와 D가 다른 집합 → ADD
        집합: {A}, {B}, {C,D}, {E}        T = {(C,D)}

Step 2: 간선 (A,C,3) — A와 C가 다른 집합 → ADD
        집합: {A,C,D}, {B}, {E}           T = {(C,D),(A,C)}

Step 3: 간선 (C,E,4) — C와 E가 다른 집합 → ADD
        집합: {A,C,D,E}, {B}              T = {(C,D),(A,C),(C,E)}

Step 4: 간선 (A,D,5) — A와 D가 같은 집합 → SKIP (사이클 형성)

Step 5: 간선 (D,E,6) — D와 E가 같은 집합 → SKIP

Step 6: 간선 (B,E,7) — B와 E가 다른 집합 → ADD
        집합: {A,B,C,D,E}                 T = {(C,D),(A,C),(C,E),(B,E)}
        |T| = 4 = n-1 → 종료

MST 가중치 총합: 2 + 3 + 4 + 7 = 16
```

```
MST (가중치 = 16):
   A         B
   |         |
  3|        7|
   |         |
   C---------E
   |       4
  2|
   |
   D
```

MST가 Prim의 결과와 **같다** (MST가 유일하면 두 알고리즘이 간선 단위로 일치한다. 가중치에 동률이 있으면 *서로 다르지만 모두 최적인* MST를 만들 수 있다).

### 4.7 Prim vs Kruskal

| | Prim | Kruskal |
|---|------|---------|
| **전략** | 한 정점에서 MST 키우기 | 전역적으로 가장 싼 간선 선택 |
| **자료구조** | 우선순위 큐 (힙) | Union-Find + 정렬된 간선 |
| **시간** | $O(E \log V)$ | $O(E \log V)$ |
| **유리한 경우** | 밀집 그래프 ($E$가 $V^2$에 근접) | 희소 그래프 ($E$가 $V$에 근접) |
| **접근** | 정점 중심 (컷 확장) | 간선 중심 (전역 간선 리스트 스캔) |
| **병렬화** | 어려움 | 쉬움 (독립적 간선 검사) |

둘 다 **그리디** 알고리즘이며 **증명적으로 최적인** MST를 만든다.

> **5주차와의 연결:** 그리디 알고리즘은 그리디 선택 성질이 성립할 때 정확히 *옳다*. MST의 경우 그 정당화가 바로 컷 성질이다 — 그리디 휴리스틱이 우연히 정리(theorem)가 되는 드문 최적화 문제 중 하나다.

| **그래프** | $G = (V, E)$; 방향/무방향; 가중치/무가중치 |
| **인접 행렬** | $O(V^2)$ 공간, $O(1)$ 간선 조회; 밀집 그래프에 적합 |
| **인접 리스트** | $O(V + E)$ 공간, $O(\deg)$ 조회; 희소 그래프에 적합 |
| **DFS** | 재귀/스택 기반; $O(V + E)$; 깊이 우선 |
| **BFS** | 큐 기반; $O(V + E)$; 레벨 단위; 최단 홉 경로 |
| **위상 정렬** | DAG 전용; $O(V + E)$; in-degree 방법 또는 DFS finish 방법 |
| **Prim MST** | 정점에서 키우기; 힙으로 extractMin; $O(E \log V)$ |
| **Kruskal MST** | 간선 정렬 + Union-Find; $O(E \log V)$ |

**핵심 정리:**
- **표현 방식이 비용을 결정한다** — 밀집은 행렬, 희소는 리스트/배열.
- DFS와 BFS는 둘 다 $O(V + E)$지만 **발견 순서** 가 다르다 — 필요한 것(깊이 vs 레벨)에 따라 고른다.
- **BFS = 무가중치 그래프의 최단 경로.** 가장 저렴한 최단 경로 알고리즘.
- **위상 정렬이 존재할 필요충분조건은 그래프가 DAG인 것.** 두 알고리즘 모두 $O(V + E)$.
- **MST는 그리디 최적이다** — Prim과 Kruskal 모두 컷 성질을 이용한다. 두 알고리즘은 "어떤 컷을 보는지"가 다르다.
- Prim vs Kruskal: 같은 복잡도, 다른 편향 — Prim은 밀집을, Kruskal은 희소를 선호한다.

> "그래프는 관계를 계산 가능하게 만드는 방법이다."

**다음 주:** 최단 경로 알고리즘 — Dijkstra, Bellman-Ford, Floyd-Warshall.

## 점검 문제

1. **표현 선택:** 평균 차수 4인 정점 $10^7$개의 도로 네트워크에 어떤 표현을 사용할 것이며 왜 그런가? 각 표현에 필요한 공간을 추정하라.

   > **정답:** 총 간선 수 $E \approx V \cdot \bar{d}/2 = 10^7 \cdot 4 / 2 = 2 \cdot 10^7$ — 매우 **희소** ($E \ll V^2$). **인접 행렬** 은 $V^2 = 10^{14}$개 원소(약 100 TB)가 필요해 완전히 불가능. **인접 리스트/배열** 은 $O(V + E) = O(3 \cdot 10^7)$개 원소(8바이트 포인터 기준 약 250 MB)면 충분하므로 메모리에 쉽게 들어간다. 따라서 **인접 리스트**(캐시 친화성을 위해 packed adjacency array도 좋음)를 사용한다. 도로 네트워크는 전형적인 희소 그래프다.

2. **DFS vs BFS 추적:** §2.3의 그래프에서 정점 6부터 시작하는 BFS와 DFS를 실행하라. 둘의 방문 순서를 보고하라.

   > **정답:** §2.3의 인접 리스트: 1:[2,3,4,6], 2:[1,3], 3:[1,2,5], 4:[1,6], 5:[3,6], 6:[1,4,5]. **6에서 BFS:** 큐 = [6]. 6 dequeue → 1, 4, 5 enqueue. 1 dequeue → 2, 3 enqueue. 4 dequeue(이웃 모두 방문됨). 5 dequeue(방문됨). 그 후 2, 3. 순서: **6 → 1 → 4 → 5 → 2 → 3**. **6에서 DFS:** 6 방문 → 1 재귀 → 2 재귀 → 3 재귀 → 5 재귀(5의 이웃 6은 이미 방문) → 백트랙 → 4. 순서: **6 → 1 → 2 → 3 → 5 → 4**.

3. **BFS 최단 경로 증명:** BFS가 정점 $v$를 처음 dequeue할 때 기록된 거리 $d[v]$가 $s$에서 $v$까지의 최단 홉 거리와 같음을 증명하라. FIFO 규율이 정확히 어디서 논증에 들어가는가?

   > **정답:** $d[v]$에 대한 귀납법. **기저:** $d[s] = 0$은 자명히 최단. **귀납:** 실제 거리 $< \ell$인 모든 정점이 올바른 $d$ 값으로 dequeue되었다고 가정. BFS가 거리 $\ell - 1$의 $u$를 dequeue하며 이웃 $v$를 처음 발견해 $d[v] = \ell$로 설정한다고 하자. 모순을 위해 $v$의 진짜 최단 거리가 $\ell' < \ell$이라 하면, $v$의 진짜 BFS 부모는 거리 $\ell' - 1 < \ell - 1$이므로 $u$보다 먼저 dequeue되었을 것이고 — "처음 발견"에 모순. **FIFO 규율** 이 결정적인 곳이 바로 이 지점이다 — FIFO가 거리 $\ell - 1$의 모든 정점이 거리 $\ell$ 정점보다 먼저 dequeue됨을 보장하므로, 더 짧은 경로가 뒤늦게 끼어들 수 없다.

4. **방향 그래프에서의 DFS:** 간선이 $\{(A,B), (B,C), (C,A), (A,D)\}$인 방향 그래프에 $A$에서 시작하는 DFS를 적용하라. 후행 간선(back edge)을 찾아라 — 그것의 존재가 그래프에 대해 무엇을 의미하는가?

   > **정답:** A에서 DFS: A 진입 → B 진입 → C 진입 → C의 이웃 A가 **DFS 스택 위에 있는(아직 finish하지 않은) 상태** → 간선 $(C, A)$는 **후행 간선(back edge)**. C 반환, B 반환 후 A는 D를 방문. 후행 간선의 존재는 방향 그래프에 **사이클** $A \to B \to C \to A$이 있음을 의미한다. 일반적으로 방향 그래프가 사이클을 가질 **필요충분 조건** 은 DFS가 후행 간선을 적어도 하나 만나는 것이다 — 이것이 DFS 기반 사이클 탐지의 원리이며, 그래프가 **DAG가 아니므로** 위상 순서가 존재하지 않는다.

5. **위상 정렬:** 간선이 $\{(1,2), (1,3), (3,4), (2,4), (4,5)\}$인 DAG에 두 위상 정렬 알고리즘을 모두 적용하라. 모든 유효한 위상 순서가 모든 간선 제약을 만족함을 보여라.

   > **정답:** **In-degree 방법:** 초기 진입 차수 1:0, 2:1, 3:1, 4:2, 5:1. 1 선택(0) → 2:0, 3:0. 2 선택 → 4:1. 3 선택 → 4:0. 4 선택 → 5:0. 5 선택. 순서: **1, 2, 3, 4, 5**. **DFS 방법** 1에서: 1 → 2 → 4 → 5; 5 finish, prepend → R=[5]; 4 finish → R=[4,5]; 2 finish → R=[2,4,5]; 3 방문 → 4 이미 처리; 3 finish → R=[3,2,4,5]; 1 finish → R=[**1,3,2,4,5**]. 두 순서 모두 유효한 이유는 모든 간선 $(x,y)$에 대해 $x$가 $y$보다 앞에 있기 때문 — 예: 1이 2, 3보다 앞, 2가 4보다 앞, 3이 4보다 앞, 4가 5보다 앞.

6. **위상 정렬 vs 사이클:** 몰래 사이클을 포함하는 그래프에 in-degree 알고리즘을 실행하라. 무엇이 잘못되는가? 알고리즘의 실패 모드로부터 사이클을 어떻게 *탐지* 할 수 있는가?

   > **정답:** 사이클 위 모든 정점은 **사이클의 다른 구성원으로부터 들어오는 간선** 을 적어도 하나 갖는다. 따라서 사이클 외부 정점을 제거하는 것만으로는 사이클 정점의 진입 차수가 0이 되지 못한다. 알고리즘은 진입 차수 0인 시작점에서 도달 가능한 모든 정점을 처리한 뒤 **사이클 정점들을 배치하지 못한 채 멈춘다**. **탐지 규칙:** 알고리즘 종료 후 `배치된 정점 수 < |V|`이면 남은 정점들이 **사이클** 을 이룬다(또는 사이클로 들어간다). 이것이 표준적인 선형 시간 DAG 검사이며, Kahn 알고리즘은 $O(V+E)$에 위상 정렬과 사이클 탐지를 동시에 해낸다.

7. **MST 컷 성질:** 컷 성질을 진술하고 증명하라 — 임의의 컷 $(S, V \setminus S)$에 대해 그 컷을 건너는 최소 가중치 간선은 *어떤* MST에 속한다. 가중치에 동률이 있을 때 "어떤"이라는 한정사가 왜 중요한가?

   > **정답:** **컷 성질:** $(S, V \setminus S)$를 임의의 비자명한 컷이라 하고 $e = (u, v)$를 $u \in S$, $v \in V \setminus S$인 최소 가중치 컷-간선이라 하자. **증명 (교환 논증):** 임의의 MST $T$를 잡는다. $e \in T$이면 끝. 아니라면 $T$에 $e$를 추가하면 사이클이 생기는데, 이 사이클은 같은 컷을 건너는 또 다른 간선 $e'$를 반드시 포함한다. $w(e) \leq w(e')$이므로 $e'$를 $e$로 교환해 $T' = T \cup \{e\} \setminus \{e'\}$를 만들면 $w(T') \leq w(T)$ — $T'$도 MST이며 $e$를 포함한다. "**어떤**"이라는 한정사가 중요한 이유는 가중치 동률이 있을 때 컷을 건너는 최소 가중치 간선이 여러 개일 수 있고, **서로 다른 MST가 서로 다른 간선을 포함할 수 있기 때문이다** — Prim과 Kruskal이 모두 최적이지만 서로 다른 MST를 만들 수 있다.

8. **Prim vs Kruskal:** §4.4의 그래프에서 Kruskal을 처음부터 실행하고, 각 단계에서 선택되는 간선을 Prim의 것과 비교하라. 두 알고리즘이 *다른* 선택을 하는 지점은 어디이며, 그래도 같은 MST가 나오는가?

   > **정답:** **Kruskal 순서**(가중치순): (C,D,2), (A,C,3), (C,E,4), (A,D,5) 건너뜀[사이클], (D,E,6) 건너뜀[사이클], (B,E,7). MST = {(C,D), (A,C), (C,E), (B,E)}, 총 가중치 16. **A에서 시작한 Prim**: (A,C,3), (C,D,2), (C,E,4), (E,B,7). **선택된 간선 집합은 동일** 하며 **선택 순서만 다르다** — Prim은 A에서 확장하므로 (A,C)를 먼저 고르고, Kruskal은 전역 최소 가중치인 (C,D)를 먼저 고른다. 가중치 동률이 없어 MST가 유일하므로 두 알고리즘은 같은 트리에 수렴한다.

9. **Union-Find:** §4.6 예시의 Kruskal 동안 union-by-rank + 경로 압축을 사용해 `Find`와 `Union` 연산을 추적하라. 각 단계 후 부모 포인터 숲을 그려라.

   > **정답:** 초기: 각 정점이 자신의 루트, 모든 rank 0. (1) **(C,D,2)**: `Find(C)=C`, `Find(D)=D`, rank 동률 → D의 부모를 C로, rank(C)=1. 숲: {A}, {B}, {C←D}, {E}. (2) **(A,C,3)**: `Find(A)=A`(rank 0), `Find(C)=C`(rank 1), A를 C 아래 부착. 숲: {C←D, A}, {B}, {E}. (3) **(C,E,4)**: `Find(C)=C`, `Find(E)=E`, E를 C 아래 부착. 숲: {C←D, A, E}, {B}. (4) **(A,D,5)**: `Find(A)`: A→C(루트, 경로 압축으로 A의 부모를 C로). `Find(D)`: D→C. 같은 루트 → **건너뜀**. (5) **(D,E,6)**: 둘 다 C를 가리킴 → 건너뜀. (6) **(B,E,7)**: `Find(B)=B`(rank 0), `Find(E)=C`(rank 1), B를 C 아래 부착. 최종 숲: 루트 C에 A, B, D, E를 자식으로 가진 단일 트리.

10. **밀도 기반 선택:** $V = 1000, E = 999$인 그래프 (거의 트리)와 $V = 1000, E = 400{,}000$인 그래프 (밀집)에 대해, 각각 어떤 MST 알고리즘을 선호할 것이며 왜인가?

    > **정답:** **희소 케이스 ($E = 999$): Kruskal.** $E \approx V$이므로 $E$개 간선 정렬은 $O(E \log E) \approx 10^4$ 비교에 그치고 Union-Find의 상수 인자는 거의 1에 가깝다 — 실용적으로 매우 빠르고 병렬화도 쉽다. **밀집 케이스 ($E = 400{,}000$, $E \approx V^2/2.5$): Prim.** 배열 기반 Prim의 $O(V^2)$ 구현이 Kruskal의 $O(E \log V) \approx 4 \cdot 10^5 \cdot 10 = 4 \cdot 10^6$를 능가하는 이유는 Prim이 $V = 1000$번의 추출만 수행하기 때문이다. Fibonacci 힙을 쓰면 Prim은 $O(E + V \log V)$ — 밀집 그래프에서 점근적으로 최적이다.
