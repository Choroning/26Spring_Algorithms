>
> **학습 목표**:
> 1. **다루기 쉬운(tractable, 다항 시간)** 문제와 **다루기 어려운(intractable)** 문제, **결정 가능(decidable)** 과 **결정 불가능(undecidable)** 을 구분할 수 있다
> 2. **P** 와 **NP** 의 정의를 진술하고 *풀기 vs 검증* 직관을 설명할 수 있다
> 3. 여러 유명한 **NP-완비 문제** (SAT, Subset Sum, Partition, 0-1 Knapsack, Vertex Cover, Independent Set, Clique, Graph Coloring, Longest Path, Set Cover, TSP, Hamiltonian Cycle, Bin Packing, Job Scheduling)를 나열할 수 있다
> 4. **결정 문제** (Yes/No)와 **최적화 문제** 를 구분하고, NP-완비성이 결정 문제로 기술되는 이유를 설명할 수 있다
> 5. **다항 시간 환원** $A \leq_P B$ 를 정의하고 어려움을 이전하는 데 사용할 수 있다
> 6. **NP-Hard** 와 **NP-Complete** 를 정의하고 **2단계 레시피** (NP 안 + 알려진 NP-C에서의 환원)로 새 문제의 NP-완비성을 증명할 수 있다
> 7. **LONGEST-PATH가 NP-Complete** 임을 증명하고 **3-SAT $\leq_P$ CLIQUE** 환원을 스케치할 수 있다
> 8. 어떤 문제가 NP-Complete임이 증명되었을 때 실제로 무엇을 할지 (heuristic, 근사, 특수 경우) 결정할 수 있다
> 9. **근사 비율(approximation ratio)** 과 그것을 증명하는 **간접 최적해(indirect-optimal)** 기법을 정의할 수 있다
> 10. TSP (MST 기반), **Vertex Cover** (maximal-matching), **Bin Packing** (FF/NF/BF/WF), **Job Scheduling** (가장 빨리 끝나는 기계), **k-Clustering** (farthest-first traversal)의 **2-근사** 를 실행하고 분석할 수 있다

## 1. 문제의 복잡도 분류

### 1.1 NP-완비성 이론이 중요한 이유

상사가 효율적 알고리즘이 떠오르지 않는 문제를 준다. 가능한 답변 셋:

- **시나리오 1:** *"효율적 알고리즘을 못 찾겠습니다. 제가 똑똑하지 못해서요."* → 부끄러움.
- **시나리오 2:** *"효율적 알고리즘은 존재하지 않습니다."* → 가장 강력하지만 비존재 증명은 어렵다.
- **시나리오 3 (NP-Complete):** *"효율적 알고리즘을 못 찾았지만, 50년 넘게 수천 명의 뛰어난 사람들도 관련된 수백 개 문제에 대해 마찬가지였습니다."* → 직업적으로 방어 가능.

> **NP-완비성 이론의 전체 요점** 은 시나리오 1을 시나리오 3으로 격상시키는 것. 정확한 다항 시간 해법 탐색을 멈추고 휴리스틱이나 근사로 선회할 *정당하고*, *이론적 기반이 있는* 근거를 제공한다.

### 1.2 문제의 분류

```
┌──────────────────────────────────────────────────────────┐
│                   ALL PROBLEMS                            │
│                                                          │
│  ┌─────────────────────────────────────────────────────┐ │
│  │  Solvable (결정 가능)                                │ │
│  │                                                     │ │
│  │  ┌───────────────────────────────────────────────┐  │ │
│  │  │  Tractable: 다항 시간                          │  │ │
│  │  │  - Shortest Path, MST, Sorting, ...           │  │ │
│  │  │  - 시간: 어떤 상수 k 에 대해 O(n^k)             │  │ │
│  │  └───────────────────────────────────────────────┘  │ │
│  │  ┌───────────────────────────────────────────────┐  │ │
│  │  │  Intractable: 알려진 다항 알고리즘 없음        │  │ │
│  │  │  *** NP-Complete 문제들이 여기 ***              │  │ │
│  │  │  - SAT, TSP, Vertex Cover, Clique, ...        │  │ │
│  │  │  - 최선 알려진: O(2^n), O(n!) 등               │  │ │
│  │  └───────────────────────────────────────────────┘  │ │
│  │  ┌───────────────────────────────────────────────┐  │ │
│  │  │  초지수: 예 Presburger 산술                    │  │ │
│  │  └───────────────────────────────────────────────┘  │ │
│  └─────────────────────────────────────────────────────┘ │
│                                                          │
│  ┌─────────────────────────────────────────────────────┐ │
│  │  Unsolvable (결정 불가능)                            │ │
│  │  - 정지 문제, Hilbert 10번째 문제 등                  │ │
│  └─────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

> **중요한 구분:** "intractable" ≠ "unsolvable". Intractable 문제는 *알고리즘이 있고*, 다만 다항 시간이 아닐 뿐. Unsolvable 문제는 *알고리즘이 전혀 없음* — 정지 문제는 시간을 얼마나 주든 결정 불가.

### 1.3 다루기 쉬운 시간 = 다항 시간

**다항 시간** — 입력 크기 $n$, 어떤 상수 $k$ 에 대해 $O(n^k)$ 로 수행 시간이 제한.

| 다루기 쉬움 (다항)        | 다루기 어려움 (초다항)               |
|---------------------------|--------------------------------------|
| $O(\log n)$               | $O(2^n)$ — 지수                       |
| $O(n)$                    | $O(n!)$ — 팩토리얼                    |
| $O(n \log n)$             | $O(n^n)$                              |
| $O(n^2), O(n^3)$          |                                       |

> **관례:** 문제가 "효율적으로 풀 수 있다"는 것은 다항 시간 알고리즘이 존재하는 **필요충분조건**. 이것이 Cobham–Edmonds thesis — 일부러 거친 선이지만 다항 클래스가 계산 모델 변경에 강건하기에 이론적 목적에는 옳은 선택.

### 1.4 유명한 NP-완비 문제들

이번 강의 나머지를 동기 부여하는 작은 동물원. (각각 NP-Complete — 증명은 뒤에 나오거나 이들 중 하나로부터 환원.)

**SAT (Boolean Satisfiability).** Boolean 변수들이 절(clause) 안에서 OR ($\lor$) 로 연결되고, 절들이 AND ($\land$) 로 연결되어 있을 때, 모든 절을 만족하는 할당을 찾는다.

$$(\overline{w} \lor x) \land (w \lor y) \land (\overline{x} \lor \overline{y} \lor z)$$

- 만족 가능: $w = T, x = T, y = F, z$ 무엇이든.
- $(x) \land (\overline{x})$ 는 **만족 불가능**.
- **NP-Complete임이 증명된 최초의 문제** (Cook, 1971; 독립적으로 Levin, 1973).

**Subset Sum.** 정수 집합 $S$ 와 목표 $K$ 가 주어졌을 때, $S$ 의 부분집합 합이 정확히 $K$ 가 되는가?
- $S = \{20, 30, 40, 80, 90\}$, $K = 200$ → $\{30, 80, 90\}$.

**Partition.** $S$ 가 주어졌을 때 합이 같은 두 부분집합으로 나눌 수 있는가?
- $S = \{20, 30, 40, 80, 90\}$ (총 260) → $\{20, 30, 80\}$ 과 $\{40, 90\}$ (각 130).
- Subset Sum은 Partition으로 다항 시간에 환원.

**0-1 Knapsack (결정 버전).** 용량 $C$, 무게 $w_i$ 와 가치 $v_i$ 인 아이템들. 총 무게 $\leq C$, 총 가치 $\geq K$ 인 부분집합이 존재하는가?

| 아이템 | 무게  | 가치 |
|--------|-------|------|
| 1      | 12 kg | 20   |
| 2      | 8 kg  | 10   |
| 3      | 6 kg  | 15   |
| 4      | 5 kg  | 25   |

- $C = 20$ 일 때: 아이템 $\{2, 3, 4\}$ — 무게 19, 가치 50.
- **왜 NP-Complete?** 6주차 DP 해법은 $O(nC)$; 하지만 $C$ 는 $\log C$ 비트로 인코딩 가능하므로 DP는 *유사 다항(pseudo-polynomial)* — $C$ 의 *값* 에 대해서는 다항, $C$ 의 *비트 길이* 에 대해서는 지수.

**그래프 문제들:**

- **Vertex Cover.** 모든 간선을 건드리는 최소 정점 집합.
- **Independent Set.** 서로 인접하지 않은 최대 정점 집합.
- **Clique.** 최대 완전 부분 그래프.
- **Graph Coloring.** 인접 정점이 다른 색이 되는 최소 색 수.
- **Longest Path.** 길이 $\geq K$ 인 단순 $s \to t$ 경로? — 놀랍게도 NP-Complete (Shortest Path는 P와 비교).
- **Set Cover.** 합집합이 전체와 같은 최소 부분집합 수.

> **아름다운 관계:** 그래프 $G = (V, E)$ 에서 $S$ 가 vertex cover **iff** $V \setminus S$ 가 independent set. $G$ 의 clique은 보완 그래프 $\overline{G}$ 의 independent set에 대응. 많은 NP-완비 문제들이 이런 자명한 쌍대성의 양면에 앉아 있다.

**투어 스타일 문제들:**

- **TSP.** 가중 완전 그래프에서 최단 Hamilton 사이클.
- **Hamiltonian Cycle.** 그래프에 *어떤* Hamilton 사이클이라도 있는가? — 모든 간선 가중치를 1로 두면 TSP가 이리로 환원.
- **Bin Packing.** $n$ 개 아이템을 용량 $C$ 의 최소 빈에 패킹.
- **Job Scheduling.** $n$ 개 작업을 $m$ 개의 동일 기계에 할당해 makespan 최소화.

### 1.5 결정 문제 vs 최적화 문제

| 측면                          | 결정 문제                                    | 최적화 문제                  |
|-------------------------------|----------------------------------------------|------------------------------|
| **답**                        | Yes 또는 No                                  | 최고의 해                    |
| **예시 (TSP)**                | "길이 $\leq K$ 인 투어가 있는가?"              | "최단 투어 길이는?"          |
| **예시 (Shortest Path)**      | "길이 $\leq 100$ 인 경로가 있는가?"            | "최단 경로 길이는?"          |

**왜 NP-완비성이 결정 문제로 기술되는가:**

- 환원 기구가 답이 Yes/No 일 때 가장 깔끔하다.
- 최적화 버전은 결정 버전보다 **적어도 같은 만큼 어려움** — "최단 투어가?"를 풀 수 있으면 "$\leq K$ 인가?"는 자명히 답할 수 있음.
- 그러므로 결정 버전의 어려움은 최적화 버전의 어려움을 *함의*. 결정 형식으로 어려움을 진술하는 것이 가장 강하고 빈틈없는 주장.

## 2. P, NP, 그리고 NP-완비성 이론

### 2.1 클래스 P

**P** = **결정 알고리즘** 으로 **다항 시간** 에 풀 수 있는 결정 문제의 집합.

- 크기 $n$ 의 임의의 입력에 대해, 어떤 고정 $k$ 에 대해 $O(n^k)$ 시간에 Yes 또는 No 를 출력.

**P의 예시:**

- 그래프가 연결되어 있는가? — BFS / DFS, $O(V + E)$.
- $u$ 에서 $v$ 까지 길이 $\leq K$ 인 최단 경로가 있는가? — Dijkstra, $O(V^2)$ 또는 $O((V+E) \log V)$.
- $n$ 개 숫자를 $\leq T$ 회 비교로 정렬할 수 있는가? — 병합 정렬, $O(n \log n)$.
- 가중치 $\leq K$ 인 MST가 있는가? — Kruskal, $O(E \log E)$.

> 이번 학기 우리가 공부한 모든 알고리즘은 **P** 의 문제를 푼다. 1–12주차 전체 목록이 여기 포함.

### 2.2 클래스 NP

**NP** = **N**ondeterministic **P**olynomial time (비결정적 다항 시간).

결정 문제가 NP에 속하는 조건: **"Yes" certificate** (제안된 해)가 주어졌을 때, certificate의 유효성을 **다항 시간에 검증** 가능.

> **중요 — 흔한 혼동:** NP는 "non-polynomial"의 약자가 **아니다**. *Nondeterministic polynomial* 의 약자로, 이상적 **비결정 기계** 가 다항 시간에 푸는 문제 클래스 — 동등하게, Yes-답이 다항 시간 **검증** 을 허용하는 문제들.

**직관적 특성화:**

- **P** = 빠르게 **풀** 수 있는 문제.
- **NP** = 빠르게 **검증** 할 수 있는 문제.

**NP의 예시:**

- **Hamiltonian Cycle:** certificate = 정점 수열; 검증 = 모든 정점이 정확히 한 번 나타나고 + 연속 쌍이 간선으로 연결됨 확인 → $O(V)$.
- **SAT:** certificate = True/False 할당; 검증 = 대입 후 각 절 확인 → $m$ 절, 절당 $k$ 리터럴이면 $O(m \cdot k)$.
- **Subset Sum:** certificate = 부분집합; 검증 = 합산해 $K$ 와 비교 → $O(n)$.

> **문제가 NP에 속함을 보이는 것은 보통 쉽다** — NP-완비성 증명에서 형식적 절차. 어려운 부분은 NP-Hardness.

### 2.3 P vs NP — 100만 달러짜리 질문

```
  가능성 (a): P ≠ NP                      가능성 (b): P = NP
       (강하게 믿는 쪽)                          (충격적)

  ┌──────────────────────┐                ┌──────────────────────┐
  │         NP           │                │                      │
  │   ┌──────────────┐   │                │       P = NP         │
  │   │      P       │   │                │                      │
  │   └──────────────┘   │                │  NP의 모든 문제가     │
  │                      │                │  다항 시간에 풀림     │
  └──────────────────────┘                └──────────────────────┘
```

- $P \subseteq NP$ 자명 (다항 시간에 풀 수 있으면 다시 실행해서 다항 시간에 검증 가능).
- $P = NP$ 인지 $P \neq NP$ 인지는 **CS의 가장 유명한 미해결 문제**.
- **Clay Millennium Prize**: 어느 쪽이든 증명 시 $1{,}000{,}000$.
- 연구자들의 압도적 합의는 $P \neq NP$ — 하지만 *증명되지 않음*.

> **왜 누구나 관심을 갖나:** $P = NP$ 라면, 이 강의의 모든 문제(인수분해, SAT, TSP, vertex cover, 모든 NP-Complete 문제)가 실용적으로 풀린다. 우리가 아는 암호학이 무너진다. 모든 것의 최적화: 계획, 일정, 신약 개발. $P \neq NP$ 증명에 평생을 바친 연구자가 많지만 아무도 성공하지 못함.

### 2.4 다항 시간 환원

이번 강의에서 가장 중요한 구성.

**정의.** 문제 $A$ 가 문제 $B$ **로 환원** ($A \leq_P B$ 로 표기) 됨은 다음을 만족하는 함수 $f$ 가 존재함:

1. $f$ 가 $A$ 의 모든 인스턴스 $\alpha$ 를 $B$ 의 인스턴스 $f(\alpha) = \beta$ 로 **다항 시간에** 변환, 그리고
2. $\alpha$ 가 $A$ 의 Yes-인스턴스 **iff** $f(\alpha)$ 가 $B$ 의 Yes-인스턴스.

**결론:** $A \leq_P B$ 이고 $B$ 가 다항 시간에 풀린다면 $A$ 도 다항 시간에 풀린다 ($B$ 로 변환해 $B$ 의 알고리즘에 물어보면 됨).

**대우(contrapositive)** 가 NP-완비성의 엔진: $A$ 가 *어렵고* $A \leq_P B$ 이면 $B$ 도 *어렵다* — $B$ 를 효율적으로 풀면 $A$ 도 효율적으로 풀려 모순.

### 2.5 환원 예시

**예시 1 — 수론 (장난감):**

- **문제 1:** 정수 $x = x_1 x_2 \dots x_n$ (자릿수 표현)이 3으로 나누어지는가?
- **문제 2:** $x_1 + x_2 + \dots + x_n$ 이 3으로 나누어지는가?

모든 입력에 대해 답이 동일 (자릿수 합 가분 규칙). 변환: 자릿수 추출 후 합산 → $O(n)$. 문제 2는 자명히 쉬우므로 문제 1도 쉬움. $\text{문제 1} \leq_P \text{문제 2}$.

**예시 2 — HAM-CYCLE $\leq_P$ TSP:**

- **HAM-CYCLE:** 그래프 $G = (V, E)$ 가 Hamilton 사이클을 가지는가?
- **TSP (결정):** 가중 완전 그래프 $G'$ 과 한계 $K$ 에서 $G'$ 가 가중치 합 $\leq K$ 인 Hamilton 사이클을 가지는가?

**변환:** HAM-CYCLE 입력 $G$ 를 받아 같은 정점 위의 완전 그래프 $G'$ 를 구성. 간선 가중치:

```
  HAM-CYCLE 인스턴스           TSP 인스턴스
  (4 정점, 5 간선)              (완전, 6 간선 모두 가중)

    a --- b                      a --1-- b
    |   / |        ═══>          |1\  /1 |1
    |  /  |                      |  \/   |
    c --- d                      c -1/∞- d

  G의 간선        → 가중치 1                K = |V|
  G에 없는 간선   → 가중치 ∞ (또는 2|V|)
```

- $G$ 가 Hamilton 사이클을 가짐 **iff** $G'$ 가 가중치 $\leq |V|$ 인 투어를 가짐.
- 변환: $O(V^2)$ — 다항.

따라서 $\text{HAM-CYCLE} \leq_P \text{TSP}$. HAM-CYCLE이 NP-Complete임이 알려져 있으므로 TSP는 NP-Hard.

### 2.6 NP-Hard와 NP-Complete — 정의

**NP-Hard.** NP의 **모든** 문제가 $A$ 로 환원되면 $A$ 가 NP-Hard:

$$\text{모든 } L \in NP \text{ 에 대해: } \quad L \leq_P A.$$

말로 하면, $A$ 는 **NP의 모든 문제만큼 어렵다**. 결정적으로, $A$ 자체가 NP에 속할 필요는 **없음** — 정지 문제는 NP-Hard지만 NP 밖 (결정 불가능).

**NP-Complete.** $A$ 가 NP-Complete:

1. $A \in NP$ (Yes-certificate가 다항 검증 가능), **그리고**
2. $A$ 가 NP-Hard.

```
  ┌──────────────────────────────────────────────┐
  │                  NP-Hard                      │
  │                                               │
  │       ┌───────────────────────────────┐       │
  │       │            NP                 │       │
  │       │                               │       │
  │       │    ┌───────────────────┐      │       │
  │       │    │        P          │      │       │
  │       │    └───────────────────┘      │       │
  │       │                               │       │
  │       │          NP-Complete           │       │
  │       │        (SAT, TSP, Clique,      │       │
  │       │      Vertex Cover, 3-SAT, …)   │       │
  │       └───────────────────────────────┘       │
  │                                               │
  │   NP-Hard 이지만 NP가 아님:                    │
  │   (정지 문제, 일반화된 체스, …)                  │
  └──────────────────────────────────────────────┘

  * P가 부분집합으로 나타나는 것은 P ≠ NP 가정 하 (널리 믿어짐).
```

- **NP-Complete = NP ∩ NP-Hard.**
- NP-Complete 문제는 NP 안에 있으므로 그것을 NP-Hard라 부르는 것도 맞다 (다만 덜 정확).

### 2.7 NP-완비성 증명 방법

**2단계 레시피.**

**Step 1** — $A \in NP$ 증명:
- $A$ 의 Yes-certificate를 다항 시간에 검증하는 알고리즘 기술.
- 보통 몇 줄; 쉬운 부분.

**Step 2** — $A$ 가 NP-Hard 증명:
- 알려진 NP-Hard (또는 NP-Complete) 문제 $C$ 를 고름.
- 다항 시간 환원 $C \leq_P A$ 를 구성.
- **양방향** 으로 Yes/No가 보존됨을 증명.

```
  다항 시간 환원
    α (C 의 인스턴스) ────f────> β = f(α) (A 의 인스턴스)
                                          │
                                  A 의 알고리즘
                                          │
                                          ▼
       Yes  ◄────────────────────────► Yes
       No   ◄────────────────────────► No

  "A 를 다항 시간에 풀 수 있다면,
   C 도 다항 시간에 풀 수 있다."
```

$\leq_P$ 의 추이성에 의해, *모든* NP 문제가 $C$ 로 환원되고 $C$ 가 $A$ 로 환원되므로 *모든* NP 문제가 $A$ 로 환원. 따라서 $A$ 는 NP-Hard. $A \in NP$ 와 합치면 $A$ 는 NP-Complete.

### 2.8 증명 — LONGEST-PATH는 NP-Complete

**정의.**

- **HAM-PATH-2-POINTS:** $G = (V, E)$ 와 정점 $s, t$ 가 주어졌을 때, $G$ 가 $s$ 에서 $t$ 로 가는 Hamilton 경로를 가지는가? — *NP-Complete임이 알려짐*.
- **LONGEST-PATH:** 가중 $G = (V, E)$, 정점 $s, t$, 상수 $K$ 가 주어졌을 때, $s$ 에서 $t$ 로 가는 총 가중치 $\geq K$ 인 단순 경로가 존재하는가?

**Step 1 — LONGEST-PATH $\in$ NP.**
- *Certificate:* $s$ 에서 $t$ 로 가는 경로를 이루는 정점 수열.
- *검증:* 연속 쌍이 $E$ 의 간선인지 확인, 가중치 합산, 합 $\geq K$ 확인.
- *시간:* $O(|V|)$.

**Step 2 — HAM-PATH-2-POINTS $\leq_P$ LONGEST-PATH.**

*변환.* HAM-PATH-2-POINTS 인스턴스 $G = (V, E)$ 와 끝점 $s, t$ 가 주어졌을 때:
- $G$ 를 그대로 복사; 모든 간선에 **가중치 1** 할당.
- $K = |V| - 1$ 설정.

```
  HAM-PATH-2-POINTS 인스턴스        LONGEST-PATH 인스턴스

  s --- a --- b                     s -1- a -1- b
  |           |          ═══>       |           |
  c --- d --- t                     c -1- d -1- t

  "Hamilton s→t 경로?"              "가중치 ≥ |V|-1 인 단순 s→t 경로?"
```

**정방향.** Hamilton $s \to t$ 경로는 모든 $|V|$ 정점을 방문하고 $|V| - 1$ 개 간선을 쓰며 (변환된 인스턴스에서) 총 가중치 $|V| - 1 = K$. 따라서 HAM-PATH Yes-인스턴스 → LONGEST-PATH Yes-인스턴스.

**역방향.** 변환된 그래프에서 가중치 $\geq |V| - 1$ 인 단순 $s \to t$ 경로는 $\geq |V| - 1$ 개 간선을 가짐. 단순 경로는 최대 $|V| - 1$ 개 간선이므로 *정확히* $|V| - 1$ 개 간선을 갖고 *모든* $|V|$ 정점을 방문 — 즉 Hamilton $s \to t$ 경로.

변환은 $O(|E|)$. 따라서 $\text{LONGEST-PATH}$ 는 NP-Hard. Step 1과 합치면 **LONGEST-PATH는 NP-Complete**. $\blacksquare$

### 2.9 스케치 — 3-SAT $\leq_P$ CLIQUE

**3-SAT.** 각 절이 정확히 3개의 리터럴을 갖는 CNF 식. 만족하는 할당이 있는가?

**CLIQUE.** 그래프 $G$ 가 크기 $k$ 의 완전 부분 그래프를 가지는가?

**환원.** $m$ 절의 3-SAT 인스턴스가 주어졌을 때 그래프 $G_\phi$ 구성:

- 각 절의 각 리터럴마다 정점 생성 (총 $3m$ 정점 — 절당 3개).
- 두 정점 사이에 간선 추가, 단:
  - 그들이 **같은 절** 에 있거나, 또는
  - 그들이 **모순적** ($x_i$ 와 $\overline{x_i}$ 같이) 이면 안 됨.
- $k = m$ (절의 수) 설정.

**왜 동작하는가.** $G_\phi$ 의 크기 $m$ clique은 절마다 리터럴 하나를 (같은 절 정점은 연결되지 않으므로) 모순 없이 (모순 쌍은 연결되지 않으므로) 선택. clique의 모든 리터럴을 True로 설정 — 모든 절이 만족됨. 역도 마찬가지로 만족 할당이 절당 참 리터럴을 고르고, 그런 선택은 clique을 이룸.

구성은 다항. 따라서 $\text{3-SAT} \leq_P \text{CLIQUE}$ 이고 CLIQUE은 NP-Hard.

### 2.10 환원의 사슬

최초의 NP-완비 증명은 Cook(1971)의 **SAT** 에 대한 것 — NP의 정의로부터 *직접* 증명 (다항 시간 비결정 튜링 기계를 Boolean 식으로 시뮬레이션할 수 있음을 보임).

이후 모든 NP-완비성 증명은 Cook의 결과를 재사용하며 **알려진 NP-Complete 문제로부터 환원**:

```
  CIRCUIT-SAT
      ↓ (환원)
     SAT
      ↓
   3-CNF-SAT
   /       \
 CLIQUE   SUBSET-SUM
   ↓
 VERTEX-COVER
   ↓
 HAM-CYCLE
   ↓
  TSP
```

오늘날 **수천 개** 의 문제가 NP-Complete로 알려져 있다. **그중 단 하나라도 다항 시간에 풀 수 있다면 모두가 다항 시간에 풀린다** — 완전히 맞물려 있다.

### 2.11 직관에 반하는 경계

비슷해 *보이는* 일부 문제들은 복잡도가 크게 다름:

| 문제                                                  | 복잡도        | 알고리즘                    |
|-------------------------------------------------------|---------------|----------------------------|
| **Shortest Path**                                     | P             | Dijkstra $O(V^2)$           |
| **Longest Path**                                      | NP-Complete   | 다항 시간 알고리즘 없음     |
| **Euler Circuit** (모든 **간선** 한 번씩)              | P             | Hierholzer $O(E)$           |
| **Hamiltonian Cycle** (모든 **정점** 한 번씩)          | NP-Complete   | 다항 시간 알고리즘 없음     |
| **2-SAT**                                             | P             | 함의 그래프 $O(n+m)$         |
| **3-SAT**                                             | NP-Complete   | 다항 시간 알고리즘 없음     |
| **2-Coloring**                                        | P             | BFS / DFS $O(V+E)$          |
| **3-Coloring**                                        | NP-Complete   | 다항 시간 알고리즘 없음     |

> **P와 NP-Complete 사이의 경계는 놀라울 만큼 얇다** — 제약 하나만 추가해도 (간선 대신 정점, 절당 2 대신 3 리터럴, 최단 대신 최장) 다항 시간 문제가 효율적 알고리즘이 없는 문제로 뒤집힌다. 여기엔 깊은 무언가가 있고 "무엇이 문제를 어렵게 만드는가?"는 활발한 연구 주제.

### 2.12 "NP-Complete" 가 실전에서 의미하는 것

문제가 NP-Complete임이 증명되면:

1. **정확한 다항 시간 알고리즘 탐색을 중단.** 어떤 NP-Complete 문제에도 50년 넘게 아무도 발견 못함. 당신도 못 함.
2. **휴리스틱 사용.** 품질 보장 없이 실용적 인스턴스에서 좋은 (보통 최적인) 해를 찾는 알고리즘.
3. **근사 알고리즘 사용.** 해 품질의 증명 가능한 한계를 가진 다항 시간 알고리즘 — §3부터의 주제.
4. **특수 경우 해결사 사용.** 많은 NP-Complete 문제가 제한된 입력에서 다항 — 트리, 평면 그래프, 제한된 treewidth 그래프 등.

> *"때로는 어떤 것이 불가능함을 아는 것이 유용하다."*
> — **Leonid Levin**, NP-완비성의 공동 발견자 (Cook과 독립).

## 3. 근사 알고리즘 — 기초

### 3.1 왜 근사인가?

NP-Complete 문제는 *어디에나* 나타난다 — 라우팅, 스케줄링, 패킹, 커버링, 클러스터링. 다항 시간에 최적해를 찾을 수 없으므로 다음 세 가지 중 **하나를 포기** 해야 한다:

1. **다항 시간** 에 해를 찾기.
2. **모든 입력** 에 대해 해를 찾기.
3. **최적** 해를 찾기.

**근사 알고리즘은 (3)을 포기** — 다항 시간에 거의 최적인 해를 **증명 가능한 품질 보장** 과 함께 찾는다. (휴리스틱도 (3)을 포기하지만 증명 가능한 보장 없이; 무작위 알고리즘은 때때로 (2)를 확률적으로 포기; 지수 시간 정확 알고리즘은 (1)을 포기.)

### 3.2 근사 비율

근사 알고리즘은 **근사 비율(approximation ratio)** 을 동반:

$$
\rho = \frac{\text{근사해의 값}}{\text{최적해의 값}}
$$

(최대화 문제는 비율을 뒤집어 항상 $\rho \geq 1$ 이 되도록 진술.)

- $\rho$ 가 $1.0$ 에 가까울수록 = 고품질.
- $\rho = 2.0$ = 최적의 2배 이내의 해 — "2-근사(2-approximation)".
- **함정:** $\rho$ 계산엔 최적값이 필요한데 그것은 우리가 못 구하는 값! 교묘한 우회가 필요하다.

### 3.3 간접 최적해 기법

닭과 달걀 문제 우회법: **쉽게 계산 가능한 최적해 경계** 를 사용해 그것에 대해 근사 비율을 증명.

**최소화 문제:**
- 계산 가능한 $L$ 로 $\text{OPT} \geq L$ (OPT의 하한) 을 찾음.
- $\text{APX} \leq c \cdot L$ 을 보임.
- 그러면 $\text{APX} \leq c \cdot \text{OPT}$, 근사 비율 $c$.

**최대화 문제:**
- 계산 가능한 $U$ 로 $\text{OPT} \leq U$ (OPT의 상한) 을 찾음.
- $\text{APX} \geq U / c$ 를 보임.
- 그러면 $\text{APX} \geq \text{OPT} / c$.

> **왜 동작하는가:** OPT 자체를 *우회*. 절대 계산하지 않음. 단지 계산 가능한 경계와 알고리즘의 출력 사이에 끼워 넣음. 이번 강의의 모든 2-근사 증명이 이 템플릿을 따른다.

## 4. TSP — MST 기반 2-근사

### 4.1 문제와 거리 공간(metric) 가정

**Traveling Salesman Problem (TSP).** 외판원이 한 도시에서 출발해 다른 모든 도시를 정확히 한 번씩 방문하고 출발지로 돌아온다. **목표:** 총 이동 거리 최소화.

**Metric TSP** 가정:

- **대칭성:** $d(A, B) = d(B, A)$.
- **삼각 부등식:** $d(A, B) \leq d(A, C) + d(C, B)$.

둘 다 유클리드 거리와 많은 실세계 비용 모델에서 성립. 삼각 부등식 없이는 TSP를 $P = NP$ 가 아닌 한 어떤 상수 인자로도 근사 불가 — metric 가정이 2-근사를 가능케 하는 것.

### 4.2 알고리즘

계획: MST를 빌려와(11주차) 순회.

**Approx_MST_TSP**(입력: $n$ 도시와 쌍별 거리)

```
1. Kruskal 또는 Prim으로 입력 그래프의 MST 계산.
2. 임의의 도시에서 시작해 MST를 DFS 순회,
   정점 방문 순서 기록.
   (각 트리 간선은 두 번 사용 — 진행 한 번, 되돌아옴 한 번.)
3. 방문 순서에서 중복 도시 제거, 각 도시의 첫 등장만 유지;
   끝에 시작 도시 추가.
4. 결과 투어 반환.
```

Step 3가 **shortcut(지름길)** 단계 — DFS가 정점을 재방문할 때 다음 미방문 정점으로 직접 "건너뜀". 삼각 부등식이 이 지름길이 대체되는 경로보다 길지 않음을 보장.

### 4.3 풀이 예시

8 도시 $A, B, C, D, E, F, G, H$ 와 MST를 고려.

**Step 1 — MST 구축.** Kruskal / Prim 적용 → 8 정점을 연결하는 트리 간선들.

**Step 2 — DFS 순회** ($A$ 에서 시작):

$$
A \to G \to E \to G \to D \to H \to C \to H \to D \to F \to B \to F \to D \to G \to A
$$

총 길이 = $2M$, $M$ = MST 총 가중치 (각 $n - 1$ 개의 트리 간선이 두 번 사용).

**Step 3 — 중복 제거** (shortcut):

$$
A \to G \to E \to \cancel{G} \to D \to H \to C \to \cancel{H} \to \cancel{D} \to F \to B \to \cancel{F} \to \cancel{D} \to \cancel{G} \to A
$$

**최종 투어:** $A \to G \to E \to D \to H \to C \to F \to B \to A$.

삼각 부등식에 의해, 결과 투어 길이 $\leq 2M$.

### 4.4 근사 비율 증명

**주장:** Approx_MST_TSP 의 근사 비율 $< 2.0$.

$M$ = MST 총 가중치, $\text{OPT}$ = 최적 TSP 투어 길이, $\text{APX}$ = 근사 투어 길이.

**Step 1.** $\text{OPT} > M$.

*왜:* 최적 투어는 모든 정점을 방문하고 시작점으로 돌아옴. 투어에서 아무 간선이나 하나 제거하면 신장 트리가 남음 (모든 정점을 건드리고, 연결되어 있고, $|V| - 1$ 간선). $M$ 이 *최소* 신장 트리 가중치이므로 $M \leq (\text{투어 - 한 간선}) < \text{OPT}$.

**Step 2.** $\text{APX} \leq 2M$.

*왜:* DFS 순회 길이는 정확히 $2M$. Step 3의 각 shortcut은 (순회의) 부분 경로 "$x \to y \to z$" 를 직접 간선 "$x \to z$" 로 대체; 삼각 부등식이 $d(x, z) \leq d(x, y) + d(y, z)$ 을 주므로 shortcut은 길이를 *감소만* 가능.

**합치면:** $\text{APX} \leq 2M < 2 \cdot \text{OPT}$, 따라서

$$
\frac{\text{APX}}{\text{OPT}} < 2.0. \qquad \blacksquare
$$

### 4.5 복잡도

| 단계 | 연산                       | 복잡도        |
|------|----------------------------|---------------|
| 1    | MST 구축 (Kruskal)         | $O(m \log m)$ |
| 1    | MST 구축 (Prim)            | $O(n^2)$      |
| 2    | DFS 순회                   | $O(n)$        |
| 3    | 중복 제거                  | $O(n)$        |

**전체:** MST 구축이 지배 → Prim으로 $O(n^2)$ 또는 Kruskal로 $O(m \log m)$.

## 5. Vertex Cover — Maximal-Matching 2-근사

### 5.1 문제

**Vertex Cover** of $G = (V, E)$: 모든 간선이 적어도 한 끝점을 가지는 부분집합 $S \subseteq V$. **목표:** 최소 크기 vertex cover.

**실세계 비유:** 모든 복도(간선)가 감시되도록 교차로에 최소 CCTV 카메라 설치.

### 5.2 알고리즘

**핵심 통찰:** 비싼 set-cover 식 환원 대신 **maximal matching** 을 만들고 모든 끝점을 취한다.

- **Matching:** 끝점을 공유하지 않는 간선 집합.
- **Maximal matching:** 더 이상 간선을 추가할 수 없는 matching (그리디 정지점) — **maximum** matching (가장 큰 것)과 다름.
- Maximal matching은 *그리디로* 다항 시간에 찾을 수 있음.

**Approx_Matching_VC**(입력: 그래프 $G = (V, E)$)

```
1. G의 maximal matching M 찾기:
   - M ← ∅
   - 각 간선 (u, v) ∈ E 에 대해:
       만약 u 도 v 도 M의 어떤 간선의 끝점이 아니면,
       (u, v) 를 M에 추가.
2. M의 모든 간선의 끝점 집합 반환.
```

### 5.3 풀이 예시와 증명

```
9 정점 그래프:
   1 --- 2 --- 3
   |   / |   / |
   4 --- 5 --- 6
   |   / |   / |
   7 --- 8 --- 9
```

그리디 maximal matching $M$ 이 6 간선을 골랐다고 하자. 알고리즘은 $2 \cdot 6 = 12$ 끝점을 반환. 최적 vertex cover가 7이라면 비율은 $12 / 7 \approx 1.71$ — 보장된 $2.0$ 안에 잘 들어옴.

**근사 비율 증명.**

**주장:** Approx_Matching_VC 의 근사 비율 $\leq 2.0$.

$|M|$ = maximal matching의 간선 수, $\text{OPT}$ = 최적 vertex cover 크기.

**Step 1.** $\text{OPT} \geq |M|$.

*왜:* 모든 vertex cover는 각 matching 간선의 적어도 한 끝점을 포함해야 함 (안 그러면 그 간선이 커버 안 됨). Matching 간선들은 끝점을 공유하지 않으므로 서로 다른 matching 간선엔 *서로 다른* 정점이 필요 — 총 $\geq |M|$ 정점.

**Step 2.** $\text{APX} = 2|M|$.

*왜:* 알고리즘이 모든 matching 간선의 두 끝점을 반환 — 정확히 $2|M|$ 개 정점, 모두 distinct (matching 간선은 끝점을 공유하지 않으므로).

**합치면:**
$$
\frac{\text{APX}}{\text{OPT}} = \frac{2|M|}{\text{OPT}} \leq \frac{2|M|}{|M|} = 2.0. \qquad \blacksquare
$$

**복잡도.** 각 간선마다 끝점이 이미 쓰였는지 확인 → 간선당 $O(n)$ × $m$ 간선 → **$O(nm)$**.

## 6. Bin Packing — 네 가지 그리디 휴리스틱

### 6.1 문제

$n$ 개 아이템(크기 $s_1, s_2, \dots, s_n$ 각 $\leq C$)과 용량 $C$ 의 빈이 주어졌을 때, 모든 아이템을 **최소 수의 빈** 에 패킹.

응용: 메모리 할당, 컨테이너 적재, 디스크 파티셔닝, 가상 머신 패킹.

### 6.2 First Fit / Next Fit / Best Fit / Worst Fit

| 방법 | 전략 |
|------|------|
| **First Fit (FF)** | 각 아이템을 충분한 공간이 있는 **첫 빈** 에 놓음. |
| **Next Fit (NF)**  | **가장 최근 사용 빈** 만 확인; 안 맞으면 새 빈 오픈. |
| **Best Fit (BF)**  | **남는 공간이 최소** 가 되도록 들어가는 빈에 놓음. |
| **Worst Fit (WF)** | **남는 공간이 최대** 가 되도록 들어가는 빈에 놓음. |

모든 방법에서, 들어갈 기존 빈이 없으면 새 빈 오픈.

```
Approx_BinPacking(아이템 s_1, …, s_n, 용량 C):
    B = 0
    for i = 1 to n:
        if 선택된 전략대로 충분한 빈이 존재:
            거기에 아이템 i 놓음
        else:
            새 빈 오픈, 아이템 i 놓음, B = B + 1
    return B
```

### 6.3 풀이 예시

$C = 10$, 아이템 $= [7, 5, 6, 4, 2, 3, 7, 5]$.

| 방법         | 빈 내용                                | 빈 사용 |
|--------------|----------------------------------------|---------|
| First Fit    | {7,3}, {5,4}, {6,2}, {7}, {5}          | 5       |
| Next Fit     | {7}, {5}, {6,4}, {2,3}, {7}, {5}       | 6       |
| Best Fit     | {7,3}, {5,4}, {6,2}, {7}, {5}          | 5       |
| Worst Fit    | {7,2}, {5,4}, {6,3}, {7}, {5}          | 5       |
| **Optimal**  | {7,3}, {5,5}, {6,4}, {7,2}             | **4**   |

### 6.4 근사 비율 증명

**주장:** First Fit / Best Fit / Worst Fit 모두 $\rho \leq 2.0$ 달성.

**핵심 관찰.** 종료 시점에 절반 미만으로 찬 빈은 최대 **하나**. *왜:* 두 빈이 각각 $<C/2$ 라면 둘의 내용이 한 빈에 들어갈 수 있음 — FF/BF/WF의 "빈을 최대한 채워라" 그리디 전략에 모순.

**증명.** $\text{OPT}'$ = 알고리즘이 사용한 빈 수, $\text{OPT}$ = 최적. 적어도 $\text{OPT}' - 1$ 개 빈이 절반 *초과* 로 차 있음:

$$
\sum s_i > (\text{OPT}' - 1) \cdot \frac{C}{2}
$$

자명하게 최적도 부피만 따져 적어도 $\sum s_i / C$ 빈 사용, 따라서 $\text{OPT} \geq \sum s_i / C$. 합치면:

$$
\text{OPT} \geq \frac{\sum s_i}{C} > \frac{\text{OPT}' - 1}{2}
\implies 2 \cdot \text{OPT} > \text{OPT}' - 1
\implies 2 \cdot \text{OPT} \geq \text{OPT}'.
\qquad \blacksquare
$$

**주장:** Next Fit도 살짝 다른 논증으로 $\rho \leq 2.0$ 달성.

**핵심 관찰.** Next Fit 하에서 *연속된* 두 빈의 내용 합은 $C$ 초과. *왜:* 두 번째 빈 내용이 첫 빈에 들어갔다면 Next Fit이 두 번째 빈을 열지 않았을 것.

**증명.** 연속 빈을 쌍으로 묶음: (bin 1, bin 2), (bin 3, bin 4), ... 적어도 $\lceil \text{OPT}' / 2 \rceil$ 쌍이 있고 각 쌍은 $> C$:

$$
\sum s_i > \frac{\text{OPT}'}{2} \cdot C
\implies \text{OPT} \geq \frac{\sum s_i}{C} > \frac{\text{OPT}'}{2}
\implies 2 \cdot \text{OPT} > \text{OPT}'.
\qquad \blacksquare
$$

**복잡도:**

| 방법 | 아이템당 작업       | 총합     |
|------|---------------------|----------|
| First Fit  | 모든 빈 스캔, $O(n)$ | $O(n^2)$ |
| Best Fit   | 모든 빈 스캔, $O(n)$ | $O(n^2)$ |
| Worst Fit  | 모든 빈 스캔, $O(n)$ | $O(n^2)$ |
| Next Fit   | 한 빈 확인, $O(1)$   | $O(n)$   |

> **실전에서**, 아이템을 *감소* 크기 순으로 먼저 정렬 (First Fit Decreasing, Best Fit Decreasing) 하면 점근적으로 $11/9$ 근처의 더 좋은 비율을 얻음 — 이 강의 범위 너머의 심층 분석.

## 7. Job Scheduling — 가장 빨리 끝나는 기계 2-근사

### 7.1 문제

- $n$ 작업, 처리 시간 $t_1, t_2, \dots, t_n$.
- $m$ 개 동일 기계 $M_1, \dots, M_m$.
- 각 작업은 한 기계에서 중단 없이 실행; 각 기계는 한 번에 한 작업.

**목표:** 작업을 기계에 할당해 **makespan** (마지막 작업의 완료 시간) 최소화.

### 7.2 알고리즘과 풀이 예시

**알고리즘.** 새 작업이 도착하면 가장 **빨리** 비는 기계에 할당:

```
Approx_JobScheduling(시간 t_1, …, t_n, m 기계):
    for j = 1 to m:
        L[j] = 0                       // 기계 j 의 현재 완료 시간
    for i = 1 to n:
        min = 1
        for j = 2 to m:
            if L[j] < L[min]:
                min = j
        작업 i 를 기계 M_min 에 할당
        L[min] = L[min] + t_i
    return max(L[1], …, L[m])
```

**풀이 예시.** 작업 $t = [5, 2, 4, 3, 4, 7, 9, 2, 4, 1]$, $m = 4$ 기계.

| 작업 | $t_i$ | 할당 | 이후 load        |
|------|-------|------|-------------------|
| 1    | 5     | M1   | [5, 0, 0, 0]      |
| 2    | 2     | M2   | [5, 2, 0, 0]      |
| 3    | 4     | M3   | [5, 2, 4, 0]      |
| 4    | 3     | M4   | [5, 2, 4, 3]      |
| 5    | 4     | M2   | [5, 6, 4, 3]      |
| 6    | 7     | M4   | [5, 6, 4, 10]     |
| 7    | 9     | M3   | [5, 6, 13, 10]    |
| 8    | 2     | M1   | [7, 6, 13, 10]    |
| 9    | 4     | M2   | [7, 10, 13, 10]   |
| 10   | 1     | M1   | [8, 10, 13, 10]   |

**Makespan (APX) = 13.**

### 7.3 근사 비율 증명

**주장:** Approx_JobScheduling 의 근사 비율 $\leq 2.0$.

**마지막** 으로 할당된 작업 (시간 순으로, 즉 makespan을 결정하는 작업)을 작업 $i$ 라 하고 시각 $T$ 에 시작한다고 하자. 그러면 $\text{APX} = T + t_i$.

**OPT의 두 하한:**

1. **부피 한계:** $\text{OPT} \geq \frac{\sum_j t_j}{m}$ — 완벽한 부하 균형이라도 어떤 기계는 적어도 평균만큼 돌아야 함.
2. **작업당 한계:** $\text{OPT} \geq t_i$ — 어떤 일정도 작업 $i$ 를 어딘가에서 처리해야 하고 그건 $t_i$.

**증명.** 작업 $i$ 는 그것을 놓을 시점에 가장 빨리 끝나는 기계에 놓였으므로, $T \leq$ ($i$ 를 놓기 직전 모든 기계 완료 시간의 평균) $\leq$ ($i$ 를 제외한 모든 작업의 평균, $i$ 가 아직 할당되지 않았으므로):

$$
T \leq \frac{\sum_{j \neq i} t_j}{m} \leq \frac{\sum_j t_j}{m} \leq \text{OPT}.
$$

$t_i \leq \text{OPT}$ 와 합치면:

$$
\text{APX} = T + t_i \leq \text{OPT} + \text{OPT} = 2 \cdot \text{OPT}. \qquad \blacksquare
$$

**복잡도:** 각 $n$ 작업마다 $m$ 기계 부하의 최솟값을 찾음 → **$O(nm)$**.

> **실전에서**, **Longest Processing Time First (LPT)** 변형 — 같은 그리디 할당 전에 작업을 $t_i$ 의 감소 순으로 정렬 — 은 $4/3$ 근사 비율을 달성하고 경험적으로 훨씬 더 좋게 동작.

## 8. k-Clustering — Farthest-First 2-근사

### 8.1 문제

**k-Clustering Problem.** 2D 평면(또는 임의의 metric 공간)의 $n$ 점과 정수 $k$ 가 주어졌을 때, 점들을 **$k$ 그룹** 으로 분할, 각 그룹에 지정된 **중심** 점. **목표:** **최대 클러스터 지름** (가장 큰 클러스터의 지름) 최소화.

응용: 추천 시스템, 데이터 마이닝, VLSI 설계, 병렬 처리, 웹 검색, 패턴 인식, 유전자 분석, 소셜 네트워크 분석.

### 8.2 알고리즘과 풀이 예시

**Farthest-First Traversal (그리디).** 중심을 하나씩 고르되, 매번 지금까지 고른 모든 중심으로부터 **가장 먼** 점을 선택.

```
Approx_k_Clusters(점 x_0, …, x_{n-1}, k > 1):
    C[1] = x_r                            // 무작위 첫 중심
    for j = 2 to k:
        각 비-중심 점 x_i 에 대해:
            D[i] = x_i 에서 임의의 기존 중심까지의 최소 거리
        C[j] = 가장 큰 D[i] 를 갖는 점 x_i
    각 비-중심 점을 가장 가까운 중심에 할당
    return 중심 C 와 클러스터 할당
```

**직관:** 중심을 멀리 펼치는 것이 모든 클러스터가 작은 영역을 덮음을 보장.

**풀이 예시, $k = 4$.**

- **Step 1:** 임의의 $C_1$ 선택.
- **Step 2:** 모든 비-중심 점에 대해 $D[i]$ 계산; $C_1$ 으로부터 가장 먼 점이 $C_2$.
- **Step 3:** 남은 각 점에 대해 $D[i] = \min(d(x_i, C_1), d(x_i, C_2))$. 가장 큰 $D[i]$ 의 점이 $C_3$. (예: $D[3] = 20$ 이 가장 큼 → $C_3 = x_3$.)
- **Step 4:** $D[i] = \min(d(x_i, C_1), d(x_i, C_2), d(x_i, C_3))$ 재계산; 가장 큰 것이 $C_4$.
- **Step 5:** 각 비-중심 점을 가장 가까운 중심에 할당.

### 8.3 근사 비율 증명

**주장:** Approx_k_Clusters 의 근사 비율 $\leq 2.0$.

**설정.** $k$ 개 중심을 고른 후, farthest-first 규칙으로 **가상의 $(k+1)$-번째 중심** $C_{k+1}$ 을 추가로 선택한다고 상상. $d$ = $C_{k+1}$ 에서 가장 가까운 기존 중심까지의 거리.

**Step 1 — $\text{OPT} \geq d$.** 이제 $k + 1$ 점이 $k$ 개의 최적 그룹으로 나뉘어야 함. **비둘기집 원리** 에 의해, 최소 한 최적 그룹이 이 $k+1$ "중심" 중 적어도 두 개를 포함. *그* 그룹의 지름은 그 안의 두 중심 사이 거리 이상이고, 그것은 (farthest-first에 의해 $k+1$ 중심 중 최소 쌍 거리가 $d$) 적어도 $d$. 따라서 $\text{OPT} \geq d$.

**Step 2 — $\text{APX} \leq 2d$.** $C_{k+1}$ 이 임의의 기존 중심으로부터 가장 먼 점이므로, **모든** 다른 점은 가장 가까운 중심으로부터 거리 $\leq d$. 따라서 각 클러스터의 반지름 $\leq d$, 지름 $\leq 2d$.

**합치면:**
$$
2 \cdot \text{OPT} \geq 2d \geq \text{APX}
\implies \frac{\text{APX}}{\text{OPT}} \leq 2.0. \qquad \blacksquare
$$

**복잡도.** 내부 루프가 $n$ 점에 대해 $k$ 중심까지의 $D[i]$ 계산 → $O(kn)$. 외부 루프 $k - 1$ 회 → $(k-1) \cdot O(kn) = O(k^2 n)$. 최종 할당 $O(kn)$. **총: $O(k^2 n)$.**

### 8.4 실용적 고려 사항

- **무작위 첫 중심:** 결과가 매번 다름; 여러 번 실행 후 최선 선택.
- **이상치 민감성:** 노이즈 점이 중심 선택을 왜곡; 이상치 제거 전처리.
- **유산:** 이는 **k-center 문제** 와 밀접; 알고리즘 자체는 **Gonzalez 알고리즘** (1985) 으로도 불림. 현대 k-means에 쓰이는 **k-means++** 초기화에 영감을 줌.

| 문제                  | 간접 최적해 경계                                       | 비율       | 시간            |

## 요약

| 개념                       | 정의                                                                              |
|----------------------------|-----------------------------------------------------------------------------------|
| **P**                      | 다항 시간에 풀 수 있는 결정 문제                                                  |
| **NP**                     | Yes-certificate를 다항 시간에 검증할 수 있는 결정 문제                            |
| **NP-Hard**                | NP의 모든 문제만큼 적어도 어려움                                                  |
| **NP-Complete**            | NP **이고** NP-Hard                                                              |
| **환원** $A \leq_P B$       | $A$ 를 다항 시간에 $B$ 로 변환, Yes/No 보존                                       |
| **근사 비율**              | $\text{APX} / \text{OPT}$, OPT의 간접 경계로 증명                                |

**핵심 정리:**

1. $P \subseteq NP$ 자명. $P = NP$ 인지는 CS에서 가장 유명한 미해결 문제.
2. NP-완비성은 문제를 *정당하게* "아마 어려움"이라고 선언하는 어휘 — 어떤 해도 관련 수천 문제를 풀어버림.
3. **NP-완비성 증명의 2단계 레시피:** (a) 문제가 NP 안임을 보임; (b) 알려진 NP-Complete 문제를 그것으로 환원.
4. 문제가 NP-Complete임이 증명되면 **휴리스틱**, **근사**, **특수 경우 알고리즘** 으로 전환.
5. **근사 비율** 이 품질의 황금 표준이고 **간접 최적해 기법** 이 보편적 증명 템플릿 — 이번 강의의 모든 2-근사 증명은 OPT를 계산 가능 경계와 알고리즘 출력 사이에 끼워 넣는다.
6. 다섯 가지 정석적 근사 알고리즘 (TSP / Vertex Cover / Bin Packing / Job Scheduling / Clustering) 모두 간단한 그리디 전략과 깔끔한 증명으로 **인자-2 보장** 달성.

> "정확히 풀 수 없다면 어려움을 증명하라. 어렵다면 근사하라 — 그리고 근사를 증명하라."

**다음 주:** 근사 알고리즘 계속 — 더 정교한 근사 전략과 PTAS / FPTAS 프레임워크.

## 점검 문제

1. **P vs NP 직관:** *풀기(solve)* 와 *검증(verify)* 라는 단어를 써서 "P" 와 "NP" 의 차이를 일상 언어로 설명하라. P의 모든 문제가 자동으로 NP에 속하는 이유는?

   > **정답:** **P** 는 다항 시간에 정확한 Yes/No 답을 처음부터 만들 수 있는 결정 문제의 클래스 — 빨리 **풀** 수 있음. **NP** 는 후보 Yes-certificate(제안된 해)가 주어지면 다항 시간에 그 유효성을 **검증** 할 수 있는 클래스. P의 모든 문제는 NP에 속하는데, 자명한 검증기는 *certificate를 무시하고 그냥 문제를 다시 푼다*: 다항 시간 해결사가 있으면 (매우 게으른) 다항 시간 검증기도 있는 것. 역 포함 — 빠른 검증이 빠른 풀이를 함의하는가? — 가 $P = NP$ 질문.

2. **결정 vs 최적화:** TSP에 두 형태가 있다. 각각을 분명히 진술하고 NP-완비성이 결정 버전으로 증명되지만 어려움이 최적화 버전으로 여전히 이전되는 이유를 설명하라.

   > **정답:** **결정 버전:** "가중 완전 그래프 $G$ 와 한계 $K$ 가 주어졌을 때, $G$ 가 총 가중치 $\leq K$ 인 투어를 갖는가?" — Yes/No. **최적화 버전:** "$G$ 의 최소 투어 가중치는?" — 숫자. NP-완비성이 결정 문제로 정의되는 이유는 환원 기구 $A \leq_P B$ 가 Yes/No 보존을 요구하기 때문. **어려움 이전** 은 최적화 버전을 풀면 결정 버전이 자명히 풀리기 때문 (최솟값 계산 후 $K$ 와 비교) — 따라서 최적화 버전은 결정 버전보다 *적어도 같은 만큼 어려움*. 결정 버전이 NP-Complete (다항 시간 알고리즘 없음, $P \neq NP$ 가정)이면 최적화 버전도 그렇다.

3. **환원의 방향:** 한 학생이 "Hamiltonian Cycle이 TSP로 환원되니 TSP가 Hamiltonian Cycle보다 쉽겠네" 라고 말한다. 옳은가 틀린가, 그리고 왜?

   > **정답:** **틀림.** $A \leq_P B$ 는 $A$ 를 $B$ 로 변환해 $B$ 의 알고리즘으로 풀 수 있다는 의미 — 따라서 $B$ 는 $A$ **만큼 적어도 어려움**. $\leq_P$ 의 방향은 "더 어렵지 않음" 과 같다 — *A* 는 *B* 보다 더 어렵지 않음, 동등하게 *B* 가 *A* 만큼 적어도 어려움. Hamiltonian Cycle이 NP-Complete이고 TSP로 환원되므로 **TSP 도 NP-Hard** (Hamiltonian Cycle만큼 적어도 어려움). 학생은 직관을 뒤집었음.

4. **LONGEST-PATH 증명:** LONGEST-PATH NP-완비성 증명의 두 핵심 방향을 재현하라. 특히, 역방향이 가중치-1 트릭을 왜 필요로 하는가?

   > **정답:** **정방향 (HAM-PATH-2-POINTS → LONGEST-PATH):** $G$ 가 $s$ 에서 $t$ 로의 Hamilton 경로를 가지면, 변환된 그래프(간선 가중치 모두 1, $K = |V| - 1$)에서 그 같은 경로가 $|V| - 1$ 개의 가중치 1 간선을 가지므로 총 가중치 $|V| - 1 \geq K$ — LONGEST-PATH Yes-인스턴스. **역방향 (LONGEST-PATH → HAM-PATH-2-POINTS):** 변환된 그래프에서 가중치 $\geq |V| - 1$ 인 단순 $s \to t$ 경로는 $\geq |V| - 1$ 개의 간선을 가짐. *단순* 경로는 최대 $|V| - 1$ 개의 간선을 가질 수 있음 (각 정점 최대 한 번 방문). 따라서 *정확히* $|V| - 1$ 개 간선을 갖고 모든 $|V|$ 정점을 방문 — Hamilton 경로. **가중치-1 트릭** 이 "경로 길이"(가중치 합)와 "간선 수"(개수)를 연결, $K = |V| - 1$ 이 *모든* 정점 방문을 강제. 균일 가중치 없이는 역방향 실패 — 긴 경로가 그냥 무거운 짧은 경로일 수도.

5. **유사 다항 역설:** 0-1 Knapsack은 $O(nC)$ DP 해법이 있는데 NP-Complete. 명백한 모순을 해소하라.

   > **정답:** NP-완비성 이론에서 "다항 시간" 은 입력의 **수치 값** 이 아닌 **비트 길이** 에 대한 다항. 용량 $C$ 는 입력에서 $\log_2 C$ 비트로 인코딩되므로 $O(nC)$ 는 입력 비트 길이에 대해 지수: $O(n \cdot 2^{\log_2 C})$. 이를 **유사 다항(pseudo-polynomial)** 이라 부름 — $C$ 의 *값* 에 대해 다항, $C$ 의 *인코딩* 에 대해 지수. 작은 $C$ (예 $C \leq 10^6$) 의 실세계 인스턴스는 DP로 빨리 풀리지만 $C \approx 2^{100}$ 인스턴스는 그렇지 않음 — NP-완비성 증명은 지수적으로 큰 $C$ 인스턴스를 구성. NP-완비성은 모든 입력 비트 길이에 대한 최악 경우.

6. **2-SAT vs 3-SAT:** 2-SAT는 P 인데 3-SAT는 NP-Complete인 이유는? 둘 사이에 변하는 성질은?

   > **정답:** **2-SAT** 는 함의 그래프로 표현 가능: 절 $(a \lor b)$ 가 $\overline{a} \implies b$ 와 $\overline{b} \implies a$ 와 동치. 이 그래프 구축 후 **강결합 요소** 찾기(12주차, Kosaraju!) 가 다항 시간 알고리즘 — 어떤 변수와 그 부정이 같은 SCC에 있지 않으면 만족 가능. **3-SAT** 는 그런 환원이 없음: 3-절 $(a \lor b \lor c)$ 는 세 옵션 *선택* 을 인코딩, 이진 함의가 아님. 그 추가 자유도가 정확히 NP가 포착하는 **비결정성** — 절당 $\geq 3$ 리터럴이 되는 순간 문제가 임의의 NP 계산을 인코딩할 수 있게 됨. 경계는 면도날같이 얇고, *왜* 추가 자유도가 문제를 NP-Hard로 만드는지 식별하는 것이 복잡도 이론의 깊은 주제.

7. **간접 최적해를 통한 근사 비율:** "$\text{APX} \leq 2 \cdot \text{OPT}$" 증명이 왜 APX를 OPT와 직접 비교하지 않고, 간접 경계 $L$ 이 어떻게 그 대체 역할을 하는지 진술하라.

   > **정답:** OPT는 우리가 계산할 수 없는 것 — 근사의 핵심이 OPT *계산을 피하는* 것. 그래서 증명은 OPT를 우리가 통제 가능한 두 양 사이에 끼움: (1) $L \leq \text{OPT}$ (최소화) 임이 증명 가능한 다항 시간 계산 가능 경계 $L$; (2) $\text{APX} \leq c \cdot L$ 임을 증명할 수 있는 알고리즘 출력 APX. 합치면 $\text{APX} \leq c \cdot L \leq c \cdot \text{OPT}$ — OPT를 절대 계산하지 않고. 간접 경계 $L$ 이 일꾼: §4–§8의 모든 2-근사 증명이 서로 다른 $L$ 선택을 끼움 (MST 가중치, matching 크기, 부피 한계, 평균 부하, 가상 $(k+1)$-번째 중심 거리).

8. **TSP 삼각 부등식:** Approx_MST_TSP 증명에서 삼각 부등식이 정확히 어디에 쓰이는가? 그것 없이는 무엇이 잘못되는가?

   > **정답:** 삼각 부등식은 **알고리즘 Step 2** (shortcut) 과 **증명 Step 2** ($\text{APX} \leq 2M$) 에 쓰임. DFS 순회의 부분 경로 "$x \to y \to z$" 를 직접 간선 "$x \to z$" 로 대체할 때 $d(x, z) \leq d(x, y) + d(y, z)$ 가 필요 — 안 그러면 shortcut이 대체되는 경로보다 *더 길* 수 있어 $\text{APX} \leq 2M$ 한계가 깨짐. **삼각 부등식 없이는:** 일반 TSP는 $P = NP$ 가 아닌 한 어떤 상수 인자로도 근사 불가 — MST-shortcut과 최적 사이 갭이 임의로 나쁜 인스턴스를 구성 가능. Metric TSP는 삼각 부등식이 shortcut을 안전하게 만드는 "착한" 경우.

9. **Vertex Cover 비율은 tight:** Maximal-matching 알고리즘이 실제로 최적 크기의 *정확히* 2배인 vertex cover를 반환할 수 있음을 보여라 (이 알고리즘으로 2-경계를 더 개선할 수 없음).

   > **정답:** 그래프가 $k$ 개의 서로 분리된 간선 — 끝점을 공유하지 않는 크기 $k$ perfect matching 만으로 이루어진 경우. 최적 vertex cover는 간선당 한 끝점 → 크기 $k$. 알고리즘은 모든 $k$ 간선을 maximal matching으로 선택 → $2k$ 끝점 반환. 비율 = $2k / k = 2.0$ **정확**. 따라서 2-근사가 tight: 이 알고리즘 개선으로는 2 이하 못 감. Vertex cover에 대해 2를 깨려면 근본적으로 다른 접근 필요 (그리고 실제로 어떤 상수 $\epsilon > 0$ 에 대해 $(2 - \epsilon)$-근사를 얻는 것은 Unique Games Conjecture 가정 하 NP-Hard 로 추측됨).

10. **Bin Packing First Fit Decreasing (FFD):** First Fit 적용 *전* 에 감소 크기로 정렬하면 실전에서 더 좋은 비율을 얻는 이유는? 직관만, 증명은 필요 없음.

    > **정답:** 무작위 순서의 First Fit은 작은 아이템을 빈 일찍 채워, 나중에 큰 아이템이 들어갈 자리가 없어 — 자기만의 거의 빈 빈에 강제로 넣게 됨. **감소 우선** 정렬은 큰 아이템을 먼저 두는데, 그때 빈에 공간이 많음, 그 뒤 작은 아이템이 잔여 틈을 채움 — 정확히 작은 아이템이 잘하는 역할. 점근적으로 FFD는 $11/9 \cdot \text{OPT} + O(1)$ 달성, FF의 $1.7 \cdot \text{OPT}$ 대신. 직관은 일반화 가능: 많은 그리디 근사에서 **"덩어리진" 아이템을 먼저 처리** 하면 작은 아이템이 끝의 채움재 역할을 해 패킹 효율이 극적으로 향상.

11. **Job Scheduling LPT 개선:** **Longest processing time first** 순서로 작업을 스케줄링하면 $2$ 대신 $4/3$ 근사를 달성하는 이유를 스케치하라.

    > **정답:** LPT를 쓰면 makespan을 결정하는 "마지막" 작업에 도달했을 때 그 작업의 처리 시간 $\leq t_n$, 여기서 $t_n$ 은 *가장 작은* 작업 시간. 이전 증명은 $T + t_i$ 를 $\text{OPT} + \text{OPT}$ 로 한계, $t_i$ 가 가장 큰 작업일 가능성을 다룸. 그러나 LPT에서는 $t_i$ (makespan 트리거 작업)가 *작음* — 만약 총 3개 이상의 작업이 $\text{OPT}/3$ 을 초과한다면 그 작업들이 더 일찍 배치되었어야 함, 모순. 자세한 사례 분석은 $\text{APX} \leq (4/3) \cdot \text{OPT}$ 를 줌. 개념적: 큰 작업을 먼저 두면 작은 작업이 끝에서 부하 균형 여유로 작동, 거기서 불일치가 덜 중요.

12. **k-Clustering 비둘기집:** $\text{OPT} \geq d$ 논증의 비둘기집 단계를 $k = 3$ 과 4 가상 중심으로 자세히 설명하라.

    > **정답:** 선택된 $k = 3$ 중심 $C_1, C_2, C_3$ 더하기 가상 $C_4$ — 총 4 "중심". 최적 해는 모든 점을 3 클러스터로 분할. **비둘기집** 에 의해 4 항목을 3 빈에 분배하면 적어도 한 빈이 $\geq 2$ 항목 보유 — 즉 어떤 최적 클러스터가 $\{C_1, C_2, C_3, C_4\}$ 중 적어도 2개를 포함. 그 클러스터의 지름은 안에 포함된 두 중심 사이 거리 이상, farthest-first 구성에 의해 $\geq d$ (네 중심 중 최소 쌍 거리). 따라서 최대 클러스터 지름 $\geq d$, 그리고 $\text{OPT} \geq d$.
